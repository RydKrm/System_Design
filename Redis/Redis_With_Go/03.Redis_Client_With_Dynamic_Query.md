# Storing & Querying Structured Permission Data in Redis with Go

_"Alright, so this is a real design problem — not a tutorial problem. You have structured, relational-looking data, and you want to cache it in Redis, which is fundamentally a key-value store. The question is: how do you bridge that gap intelligently? Let me walk you through the whole thing."_

---

## Understanding the Problem First

Your data looks like this:

```
Permission {
    user_id      string
    module_id    string
    area_id      string
    company_id   string
    is_read      bool
    is_write     bool
    is_sync_log  bool
    is_back_date bool
}
```

And your query patterns are:

```
Query 1:  GET permissions WHERE user_id = "U001"
Query 2:  GET permissions WHERE module_id = "M005"
Query 3:  GET permissions WHERE user_id = "U001" AND module_id = "M005"
Query 4:  GET permissions WHERE user_id = "U001" AND module_id = "M005"
                            AND area_id = "A002" AND company_id = "C001"
```

Now here is the fundamental challenge. Redis does not have a `WHERE` clause. It does not have columns. It is not a database. It is a key-value store, which means the only way to look something up is by its exact key. So the entire design problem reduces to one question: **how do you design your keys so that any query pattern you need maps directly to a key lookup?**

The answer is a pattern called **Key Composition with Multiple Index Sets**. Let me explain exactly what that means.

---

## The Core Strategy: Composite Keys + Index Sets

Think of it this way. Redis gives you two powerful tools:

**Tool 1 — Hash** (`HSET`/`HGETALL`): Stores a structured object — like a Go struct — under a single key. This is where the actual permission data lives.

**Tool 2 — Set** (`SADD`/`SMEMBERS`): Stores a group of keys. This is your index — a lookup table that says "here are all the permission keys that belong to user U001."

The pattern works like this:

```
                    ┌──────────────────────────────────────────────────────────┐
                    │  Redis Memory                                            │
                    │                                                          │
                    │  ── The actual data (Hashes) ──────────────────────      │
                    │                                                          │
                    │  perm:U001:M005:A002:C001  →  { is_read: 1,              │
                    │                                  is_write: 1,            │
                    │                                  is_sync_log: 0,         │
                    │                                  is_back_date: 0 }       │
                    │                                                          │
                    │  perm:U001:M003:A001:C001  →  { is_read: 1,              │
                    │                                  is_write: 0, ... }      │
                    │                                                          │
                    │  ── Index Sets (who points to what) ────────────────     │
                    │                                                          │
                    │  idx:user:U001      →  { perm:U001:M005:A002:C001,       │
                    │                          perm:U001:M003:A001:C001 }      │
                    │                                                          │
                    │  idx:module:M005    →  { perm:U001:M005:A002:C001,       │
                    │                          perm:U002:M005:A001:C001 }      │
                    │                                                          │
                    │  idx:user:U001:module:M005 → { perm:U001:M005:A002:C001} │
                    │                                                          │
                    └──────────────────────────────────────────────────────────┘
```

The key insight is this: the index sets don't store the actual data. They store the names of the keys that hold the actual data. So a query like "give me all permissions for user U001" becomes:

```
Step 1: SMEMBERS idx:user:U001
        → ["perm:U001:M005:A002:C001", "perm:U001:M003:A001:C001"]

Step 2: HGETALL perm:U001:M005:A002:C001
        HGETALL perm:U001:M003:A001:C001
        (sent as a pipeline — one network round trip)

Step 3: Decode results → []Permission{}
```

Three steps, two network round trips (or one if you pipeline both steps). This is fast, deterministic, and scales well.

## The Key Design

Before writing a single line of Go, you need to lock down your key naming scheme. Here is what we use for HR360:

```
┌─────────────────────────────────────────────────────────────────┐
│  Key Type          Pattern                          TTL         │
│─────────────────────────────────────────────────────────────────│
│  Permission Hash   perm:{uid}:{mid}:{aid}:{cid}    30 min       │
│                                                                 │
│  Index: by user    idx:perm:user:{uid}              30 min      │
│  Index: by module  idx:perm:module:{mid}            30 min      │
│  Index: by user+   idx:perm:user:{uid}:module:{mid} 30 min      │
│         module                                                  │
│  Index: by all 4   idx:perm:{uid}:{mid}:{aid}:{cid} 30 min      │
│         fields                                                  │
└─────────────────────────────────────────────────────────────────┘
```

The permission hash key — `perm:U001:M005:A002:C001` — is the exact, fully-qualified key. When you know all four identifiers, you go straight to this key and skip the index entirely. That is your fastest path and covers Query 4.

The index sets — `idx:perm:user:U001`, `idx:perm:module:M005`, `idx:perm:user:U001:module:M005` — are secondary lookup tables for when you only know part of the identity. They each hold a set of fully-qualified permission keys that match that partial identity.

## The Complete Go Implementation

### Step 1: Define the Data Structures

```go
package permission

import (
    "context"
    "encoding/json"
    "fmt"
    "time"

    "github.com/redis/go-redis/v9"
)

// Permission represents a single row of user-module permission data.
// These are the fields we store in Redis as a Hash.
type Permission struct {
    UserID      string `json:"user_id"`
    ModuleID    string `json:"module_id"`
    AreaID      string `json:"area_id"`
    CompanyID   string `json:"company_id"`
    IsRead      bool   `json:"is_read"`
    IsWrite     bool   `json:"is_write"`
    IsSyncLog   bool   `json:"is_sync_log"`
    IsBackDate  bool   `json:"is_back_date"`
}

// QueryFilter is what the caller passes in to describe the query they want.
// Any field left empty ("") is treated as "not part of this query."
type QueryFilter struct {
    UserID    string
    ModuleID  string
    AreaID    string
    CompanyID string
}

const defaultTTL = 30 * time.Minute
```

### Step 2: Key Builder Functions

These functions are the heart of the design. Every key in Redis is derived from these functions — nowhere else. If you need to change the key format in the future, you change it in one place.

```go
// permHashKey returns the key for a single permission's Hash.
// This is the fully-qualified key — all four identifiers are known.
// Example: perm:U001:M005:A002:C001
func permHashKey(userID, moduleID, areaID, companyID string) string {
    return fmt.Sprintf("perm:%s:%s:%s:%s", userID, moduleID, areaID, companyID)
}

// indexKey builds an index Set key based on which fields are provided.
// Empty fields are skipped. This is how one function covers all query patterns.
//
// Examples:
//   indexKey("U001", "", "", "")       → "idx:perm:user:U001"
//   indexKey("", "M005", "", "")       → "idx:perm:module:M005"
//   indexKey("U001", "M005", "", "")   → "idx:perm:user:U001:module:M005"
func indexKey(userID, moduleID, areaID, companyID string) string {
    key := "idx:perm"
    if userID != "" {
        key += ":user:" + userID
    }
    if moduleID != "" {
        key += ":module:" + moduleID
    }
    if areaID != "" {
        key += ":area:" + areaID
    }
    if companyID != "" {
        key += ":company:" + companyID
    }
    return key
}
```

### Step 3: The Cache Service

```go
// Cache is the service layer that wraps all Redis permission operations.
// Inject this wherever you need to read or write permissions.
type Cache struct {
    rdb *redis.Client
    ttl time.Duration
}

func NewCache(rdb *redis.Client) *Cache {
    return &Cache{
        rdb: rdb,
        ttl: defaultTTL,
    }
}
```

### Step 4: Writing a Permission to Redis

When you write one permission, you do two things at once:

1. Store the actual data in a Hash under the fully-qualified key.
2. Add that key into every relevant index set.

```go
// Set writes a single Permission to Redis and registers it in all relevant indexes.
// Always call this after writing to PostgreSQL, never before.
func (c *Cache) Set(ctx context.Context, p Permission) error {
    // Convert the struct to a map[string]interface{} for HSET.
    // We store booleans as "1"/"0" strings because Redis Hash values are strings.
    fields := map[string]interface{}{
        "user_id":      p.UserID,
        "module_id":    p.ModuleID,
        "area_id":      p.AreaID,
        "company_id":   p.CompanyID,
        "is_read":      boolToStr(p.IsRead),
        "is_write":     boolToStr(p.IsWrite),
        "is_sync_log":  boolToStr(p.IsSyncLog),
        "is_back_date": boolToStr(p.IsBackDate),
    }

    // The fully-qualified key for this permission's data.
    dataKey := permHashKey(p.UserID, p.ModuleID, p.AreaID, p.CompanyID)

    // Use a pipeline to send all writes in a single network round trip.
    // Without a pipeline, each command below would be a separate TCP call.
    pipe := c.rdb.Pipeline()

    // Write the Hash data.
    pipe.HSet(ctx, dataKey, fields)
    pipe.Expire(ctx, dataKey, c.ttl)

    // Register this key in every index that a future query might look it up by.
    // Index 1: by user only
    idxUser := indexKey(p.UserID, "", "", "")
    pipe.SAdd(ctx, idxUser, dataKey)
    pipe.Expire(ctx, idxUser, c.ttl)

    // Index 2: by module only
    idxModule := indexKey("", p.ModuleID, "", "")
    pipe.SAdd(ctx, idxModule, dataKey)
    pipe.Expire(ctx, idxModule, c.ttl)

    // Index 3: by user + module (very common query pattern)
    idxUserModule := indexKey(p.UserID, p.ModuleID, "", "")
    pipe.SAdd(ctx, idxUserModule, dataKey)
    pipe.Expire(ctx, idxUserModule, c.ttl)

    // Index 4: by all four fields (this IS the data key itself, but
    // we keep a consistent index pattern for uniform query logic)
    idxFull := indexKey(p.UserID, p.ModuleID, p.AreaID, p.CompanyID)
    pipe.SAdd(ctx, idxFull, dataKey)
    pipe.Expire(ctx, idxFull, c.ttl)

    // Execute all commands in one shot.
    if _, err := pipe.Exec(ctx); err != nil {
        return fmt.Errorf("permission cache: failed to set permission for user %s module %s — %w",
            p.UserID, p.ModuleID, err)
    }

    return nil
}

// SetMany writes a slice of permissions to Redis.
// It pipelines all operations into a single network round trip —
// critical when you are loading an entire user's permission set on login.
func (c *Cache) SetMany(ctx context.Context, perms []Permission) error {
    if len(perms) == 0 {
        return nil
    }

    pipe := c.rdb.Pipeline()

    for _, p := range perms {
        dataKey := permHashKey(p.UserID, p.ModuleID, p.AreaID, p.CompanyID)
        fields := map[string]interface{}{
            "user_id":      p.UserID,
            "module_id":    p.ModuleID,
            "area_id":      p.AreaID,
            "company_id":   p.CompanyID,
            "is_read":      boolToStr(p.IsRead),
            "is_write":     boolToStr(p.IsWrite),
            "is_sync_log":  boolToStr(p.IsSyncLog),
            "is_back_date": boolToStr(p.IsBackDate),
        }

        pipe.HSet(ctx, dataKey, fields)
        pipe.Expire(ctx, dataKey, c.ttl)

        // Register in indexes
        for _, idxKey := range buildIndexKeys(p, dataKey) {
            pipe.SAdd(ctx, idxKey, dataKey)
            pipe.Expire(ctx, idxKey, c.ttl)
        }
    }

    if _, err := pipe.Exec(ctx); err != nil {
        return fmt.Errorf("permission cache: bulk set failed — %w", err)
    }

    return nil
}

// buildIndexKeys returns all index keys that a given permission should be registered in.
// Keeping this logic in one helper ensures Set and SetMany stay consistent.
func buildIndexKeys(p Permission, dataKey string) map[string]string {
    return map[string]string{
        "by_user":        indexKey(p.UserID, "", "", ""),
        "by_module":      indexKey("", p.ModuleID, "", ""),
        "by_user_module": indexKey(p.UserID, p.ModuleID, "", ""),
        "by_all":         indexKey(p.UserID, p.ModuleID, p.AreaID, p.CompanyID),
    }
}
```

### Step 5: Querying Permissions

This is where the design pays off. Every query pattern, regardless of how many fields are provided, follows the exact same logic.

```go
// Query fetches permissions from Redis that match the given filter.
// It figures out internally which strategy to use based on which fields are set.
//
//   filter{UserID: "U001"}                             → all perms for user U001
//   filter{ModuleID: "M005"}                           → all perms for module M005
//   filter{UserID: "U001", ModuleID: "M005"}           → all perms for user+module
//   filter{UserID: "U001", ModuleID: "M005",
//           AreaID: "A002", CompanyID: "C001"}         → exact single permission
func (c *Cache) Query(ctx context.Context, f QueryFilter) ([]Permission, error) {
    // Special case: if all four fields are known, skip the index lookup entirely.
    // We can go straight to the Hash key. This is the fastest possible path.
    if f.UserID != "" && f.ModuleID != "" && f.AreaID != "" && f.CompanyID != "" {
        return c.getByExactKey(ctx, f.UserID, f.ModuleID, f.AreaID, f.CompanyID)
    }

    // For all other cases, look up the index set to find which data keys match.
    return c.getByIndex(ctx, f)
}

// getByExactKey is the fast path — all four fields are known, so we skip the index.
func (c *Cache) getByExactKey(ctx context.Context, userID, moduleID, areaID, companyID string) ([]Permission, error) {
    dataKey := permHashKey(userID, moduleID, areaID, companyID)

    result, err := c.rdb.HGetAll(ctx, dataKey).Result()
    if err != nil {
        return nil, fmt.Errorf("permission cache: HGETALL failed for key %s — %w", dataKey, err)
    }

    // HGetAll returns an empty map (not an error) when the key doesn't exist.
    // This is our cache miss signal.
    if len(result) == 0 {
        return nil, nil // caller interprets nil as cache miss
    }

    perm := mapToPermission(result)
    return []Permission{perm}, nil
}

// getByIndex uses the index set to find all matching permission keys,
// then fetches the actual data for each one in a pipeline.
func (c *Cache) getByIndex(ctx context.Context, f QueryFilter) ([]Permission, error) {
    // Build the index key from whatever fields are available.
    idxKey := indexKey(f.UserID, f.ModuleID, f.AreaID, f.CompanyID)

    // Step 1: Get all permission keys from the index set.
    dataKeys, err := c.rdb.SMembers(ctx, idxKey).Result()
    if err != nil {
        return nil, fmt.Errorf("permission cache: SMEMBERS failed for index %s — %w", idxKey, err)
    }

    // Empty set means no cached permissions for this query — cache miss.
    if len(dataKeys) == 0 {
        return nil, nil
    }

    // Step 2: Fetch the actual Hash data for all keys in a single pipeline.
    // Without a pipeline, N keys means N round trips. With a pipeline, it's 1.
    pipe := c.rdb.Pipeline()

    cmds := make([]*redis.MapStringStringCmd, len(dataKeys))
    for i, key := range dataKeys {
        cmds[i] = pipe.HGetAll(ctx, key)
    }

    if _, err := pipe.Exec(ctx); err != nil && err != redis.Nil {
        return nil, fmt.Errorf("permission cache: pipeline HGETALL failed — %w", err)
    }

    // Step 3: Decode all results.
    var permissions []Permission
    for _, cmd := range cmds {
        data, err := cmd.Result()
        if err != nil || len(data) == 0 {
            // This key may have expired between SMEMBERS and HGETALL.
            // That's fine — skip it. The index will self-clean over time.
            continue
        }
        permissions = append(permissions, mapToPermission(data))
    }

    return permissions, nil
}
```

### Step 6: Cache Invalidation (Delete)

When permissions change in PostgreSQL, you must clean the cache. You delete the data key and remove it from every index it was registered in.

```go
// Delete removes a permission from Redis and cleans it from all indexes.
// Call this immediately after updating or deleting the permission in PostgreSQL.
func (c *Cache) Delete(ctx context.Context, p Permission) error {
    dataKey := permHashKey(p.UserID, p.ModuleID, p.AreaID, p.CompanyID)

    pipe := c.rdb.Pipeline()

    // Delete the actual Hash data.
    pipe.Del(ctx, dataKey)

    // Remove this key from every index it belongs to.
    pipe.SRem(ctx, indexKey(p.UserID, "", "", ""), dataKey)
    pipe.SRem(ctx, indexKey("", p.ModuleID, "", ""), dataKey)
    pipe.SRem(ctx, indexKey(p.UserID, p.ModuleID, "", ""), dataKey)
    pipe.SRem(ctx, indexKey(p.UserID, p.ModuleID, p.AreaID, p.CompanyID), dataKey)

    if _, err := pipe.Exec(ctx); err != nil {
        return fmt.Errorf("permission cache: delete failed for user %s module %s — %w",
            p.UserID, p.ModuleID, err)
    }

    return nil
}

// DeleteAllForUser removes every permission for a given user from Redis.
// Use this when a user's entire permission set is refreshed — e.g. after a role change.
func (c *Cache) DeleteAllForUser(ctx context.Context, userID string) error {
    idxKey := indexKey(userID, "", "", "")

    // Get all permission keys for this user.
    dataKeys, err := c.rdb.SMembers(ctx, idxKey).Result()
    if err != nil {
        return fmt.Errorf("permission cache: failed to get user index for %s — %w", userID, err)
    }

    if len(dataKeys) == 0 {
        return nil // nothing to delete
    }

    pipe := c.rdb.Pipeline()

    // Delete each permission hash.
    for _, key := range dataKeys {
        pipe.Del(ctx, key)
    }

    // Delete the user index itself.
    pipe.Del(ctx, idxKey)

    if _, err := pipe.Exec(ctx); err != nil {
        return fmt.Errorf("permission cache: bulk delete failed for user %s — %w", userID, err)
    }

    return nil
}
```

### Step 7: The Cache-Aside Pattern Wired Together

This is the service layer that your HTTP handlers actually call. The cache is invisible to the handler — it just calls `GetPermissions` and gets back data.

```go
// PermissionService is what your Gin handlers interact with.
// It owns the cache-aside logic: try cache first, fall back to DB, populate cache.
type PermissionService struct {
    repo  PermissionRepository // your PostgreSQL repository
    cache *Cache
}

// GetPermissions fetches permissions matching the filter.
// It is the only function your handlers need to call.
func (s *PermissionService) GetPermissions(ctx context.Context, f QueryFilter) ([]Permission, error) {
    // Step 1: Try the cache.
    cached, err := s.cache.Query(ctx, f)
    if err != nil {
        // Cache read failed. Log it and fall through to the database.
        // We never fail the entire request because Redis had an error.
        // Degraded performance is acceptable. Broken functionality is not.
        fmt.Printf("permission service: cache query error (falling through to db): %v\n", err)
    }

    if cached != nil {
        return cached, nil // cache hit
    }

    // Step 2: Cache miss. Go to PostgreSQL.
    perms, err := s.repo.Query(ctx, f)
    if err != nil {
        return nil, fmt.Errorf("permission service: db query failed — %w", err)
    }

    if len(perms) == 0 {
        return perms, nil
    }

    // Step 3: Populate the cache asynchronously.
    // We don't make the caller wait for the cache write.
    go func() {
        writeCtx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
        defer cancel()
        if err := s.cache.SetMany(writeCtx, perms); err != nil {
            fmt.Printf("permission service: cache population failed: %v\n", err)
        }
    }()

    return perms, nil
}

// UpdatePermission updates a permission in the database and invalidates the cache.
func (s *PermissionService) UpdatePermission(ctx context.Context, p Permission) error {
    // Write to source of truth first.
    if err := s.repo.Update(ctx, p); err != nil {
        return fmt.Errorf("permission service: update failed — %w", err)
    }

    // Invalidate the cache. Next read will fetch fresh from the DB.
    if err := s.cache.Delete(ctx, p); err != nil {
        // Log but don't fail. TTL will clean it up in 30 minutes at worst.
        fmt.Printf("permission service: cache invalidation failed: %v\n", err)
    }

    return nil
}
```

```go
// boolToStr converts a bool to "1" or "0" for Redis Hash storage.
// Redis Hash values are always strings, so we need a consistent encoding.
func boolToStr(b bool) string {
    if b {
        return "1"
    }
    return "0"
}

// strToBool converts "1"/"true" to true, everything else to false.
func strToBool(s string) bool {
    return s == "1" || s == "true"

// mapToPermission converts a Redis HGETALL result (map[string]string)
// back into a Permission struct.
```

## What Happens in Redis for Each Query

Here is a concrete walkthrough of every query pattern with the actual Redis commands being sent under the hood.

### Query 1 — by user_id only

```
Go call:   cache.Query(ctx, QueryFilter{UserID: "U001"})

Redis:
  SMEMBERS idx:perm:user:U001
  → ["perm:U001:M005:A002:C001", "perm:U001:M003:A001:C001"]

  HGETALL perm:U001:M005:A002:C001   ┐
  HGETALL perm:U001:M003:A001:C001   ┘  (pipelined — 1 round trip)

Result:  []Permission{ {U001, M005, A002, C001, ...}, {U001, M003, A001, C001, ...} }
```

### Query 2 — by module_id only

```
Go call:   cache.Query(ctx, QueryFilter{ModuleID: "M005"})

Redis:
  SMEMBERS idx:perm:module:M005
  → ["perm:U001:M005:A002:C001", "perm:U002:M005:A001:C001"]

  HGETALL perm:U001:M005:A002:C001   ┐
  HGETALL perm:U002:M005:A001:C001   ┘  (pipelined)

Result:  []Permission{ {U001, M005, ...}, {U002, M005, ...} }
```

### Query 3 — by user_id + module_id

```
Go call:   cache.Query(ctx, QueryFilter{UserID: "U001", ModuleID: "M005"})

Redis:
  SMEMBERS idx:perm:user:U001:module:M005
  → ["perm:U001:M005:A002:C001"]

  HGETALL perm:U001:M005:A002:C001

Result:  []Permission{ {U001, M005, A002, C001, ...} }
```

### Query 4 — by all four fields (fastest path, no index needed)

```
Go call:   cache.Query(ctx, QueryFilter{
               UserID: "U001", ModuleID: "M005",
               AreaID: "A002", CompanyID: "C001",
           })

Redis:
  HGETALL perm:U001:M005:A002:C001   ← direct lookup, index skipped entirely

Result:  []Permission{ {U001, M005, A002, C001, ...} }
```

## The Full Memory Layout in Redis

After writing two permissions for two users across two modules, here is exactly what lives in Redis:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Redis Keys After Writing Two Permissions                                   │
│                                                                             │
│  ── Hashes (actual data) ─────────────────────────────────────────────────  │
│                                                                             │
│  perm:U001:M005:A002:C001                                                   │
│    user_id      → "U001"                                                    │
│    module_id    → "M005"                                                    │
│    area_id      → "A002"                                                    │
│    company_id   → "C001"                                                    │
│    is_read      → "1"                                                       │
│    is_write     → "1"                                                       │
│    is_sync_log  → "0"                                                       │
│    is_back_date → "0"                                                       │
│    TTL: 1800s                                                               │
│                                                                             │
│  perm:U002:M005:A001:C001                                                   │
│    user_id      → "U002"                                                    │
│    module_id    → "M005"                                                    │
│    area_id      → "A001"                                                    │
│    company_id   → "C001"                                                    │
│    is_read      → "1"                                                       │
│    is_write     → "0"                                                       │
│    is_sync_log  → "1"                                                       │
│    is_back_date → "0"                                                       │
│    TTL: 1800s                                                               │
│                                                                             │
│  ── Sets (indexes) ──────────────────────────────────────────────────────   │
│                                                                             │
│  idx:perm:user:U001                                                         │
│    members → { "perm:U001:M005:A002:C001" }                                 │
│    TTL: 1800s                                                               │
│                                                                             │
│  idx:perm:user:U002                                                         │
│    members → { "perm:U002:M005:A001:C001" }                                 │
│    TTL: 1800s                                                               │
```

## Why Not Just Use JSON String?

You might be thinking: "why not just `SET perm:U001 '{...json...}'` and be done with it?" That is a fair question and here is the honest answer.

If you stored permissions as a JSON string under a single key per user, you would get fast reads for Query 1 (by user only). But you would have no way to query by module without loading every user's permissions and filtering in Go — which defeats the entire purpose of caching. You also could not do partial updates — changing `is_write` for one module would require fetching, deserializing, modifying, re-serializing, and re-writing the entire blob.

The Hash approach gives you field-level granularity. The Index Set approach gives you query flexibility. Together they make Redis behave like a read-optimized secondary store without losing the ability to answer arbitrary queries.

## Summary

```
┌──────────────────────────────────────────────────────────────────────────┐
│  The Mental Model                                                        │
│                                                                          │
│  Write one permission:                                                   │
│    → HSET  perm:{uid}:{mid}:{aid}:{cid}   (data)                         │
│    → SADD  idx:perm:user:{uid}            (index)                        │
│    → SADD  idx:perm:module:{mid}          (index)                        │
│    → SADD  idx:perm:user:{uid}:module:{mid}  (index)                     │
│    → SADD  idx:perm:{uid}:{mid}:{aid}:{cid}  (index)                     │
│                                                                          │
│  Query by partial fields:                                                │
│    → SMEMBERS idx:perm:{whatever fields you have}                        │
│    → HGETALL  each returned key  (pipelined)                             │
│                                                                          │
│  Query by all four fields (exact match):                                 │
│    → HGETALL  perm:{uid}:{mid}:{aid}:{cid}  (direct, no index needed)    │
│                                                                          │
│  Delete a permission:                                                    │
│    → DEL   perm:{uid}:{mid}:{aid}:{cid}                                  │
│    → SREM  from every index it was registered in                         │
│                                                                          │
│  TTL on everything: 30 minutes                                           │
│  Every key expires automatically — no manual cleanup needed              │
└──────────────────────────────────────────────────────────────────────────┘
```

This design supports every query pattern you described, is fast for all of them, and stays correct through updates and deletes. The index sets are your query routing layer, and the Hash keys are your data layer. Keep those two responsibilities cleanly separated and this will serve HR360 well in production.
