# Redis Permission Cache — One Query Pattern, One Invalidation Strategy

_"Good. This is the right call. The previous design supported multiple query patterns, which meant multiple indexes, more writes, more complexity. But you told me your query is always the same shape: give me the permission for this exact user + module + area + company. That is the simplest and fastest case in Redis. Let me show you exactly what that looks like."_

---

## The Simplified Mental Model

When your query is always fully-qualified — meaning you always know all four fields — you do not need any index at all. You construct the key, you go straight to Redis, you get the data back. One step.

```
  Your Query (always this exact shape):
  GET permission WHERE user_id    = "U001"
                   AND module_id  = "M005"
                   AND area_id    = "A002"
                   AND company_id = "C001"

  Translates directly to:
  HGETALL perm:U001:M005:A002:C001

  That is it. No SMEMBERS. No index lookup. No pipeline needed.
  Just one key, one command.
```

But you also said: when you need to invalidate, you delete by `user_id`. Meaning when a user's permissions change, you want to wipe everything belonging to that user in one shot. That requires one lightweight index — just one Set that tracks which keys belong to each user. Nothing more.

```
┌───────────────────────────────────────────────────────────────────┐
│  Redis Memory Layout (Final Design)                               │
│                                                                   │
│  ── Data Hashes ─────────────────────────────────────────────     │
│                                                                   │
│  perm:U001:M005:A002:C001  →  { is_read, is_write, ... }          │
│  perm:U001:M003:A001:C001  →  { is_read, is_write, ... }          │
│  perm:U002:M005:A002:C001  →  { is_read, is_write, ... }          │
│                                                                   │
│  ── ONE Index (user → their permission keys) ────────────────     │
│                                                                   │
│  user_perms:U001  →  { "perm:U001:M005:A002:C001",                │
│                         "perm:U001:M003:A001:C001" }              │
│                                                                   │
│  user_perms:U002  →  { "perm:U002:M005:A002:C001" }               │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

The data Hashes answer the read query. The `user_perms:{user_id}` Set answers the delete-by-user operation. That is the entire design.

## The Two Key Patterns

There are exactly two key patterns in this system. You need to memorize these because every function you write derives from them.

```
┌─────────────────────────────────────────────────────────────────┐
│  Key 1 — Permission Hash (the actual data)                      │
│                                                                 │
│  perm:{user_id}:{module_id}:{area_id}:{company_id}              │
│                                                                 │
│  Example:  perm:U001:M005:A002:C001                             │
│  Type:     Hash (HSET / HGETALL)                                │
│  TTL:      30 minutes                                           │
│  Purpose:  Store the permission fields for exact lookup         │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│  Key 2 — User Index (for invalidation only)                     │
│                                                                 │
│  user_perms:{user_id}                                           │
│                                                                 │
│  Example:  user_perms:U001                                      │
│  Type:     Set (SADD / SMEMBERS / SREM)                         │
│  TTL:      30 minutes                                           │
│  Purpose:  Track all permission keys owned by this user         │
│            so we can delete them all at once                    │
└─────────────────────────────────────────────────────────────────┘
```

## The Three Operations

Your entire system needs exactly three Redis operations. Read, Write, and Invalidate. Let me walk through what each one does before showing the code.

### Read — How a Query Works

```
  Caller has: user_id="U001", module_id="M005", area_id="A002", company_id="C001"

  Step 1: Build the key
          key = "perm:U001:M005:A002:C001"

  Step 2: HGETALL perm:U001:M005:A002:C001

  Step 3: Redis returns either:
          a) A map of fields → decode into Permission struct → return
          b) Empty map       → cache miss → go to PostgreSQL

  Total Redis round trips: 1
```

### Write — How Storing a Permission Works

```
  Step 1: Build the data key
          dataKey = "perm:U001:M005:A002:C001"

  Step 2: Build the user index key
          indexKey = "user_perms:U001"

  Step 3: Send both commands in one pipeline:
          HSET  perm:U001:M005:A002:C001   user_id U001 module_id M005 ...
          EXPIRE perm:U001:M005:A002:C001  1800
          SADD  user_perms:U001            "perm:U001:M005:A002:C001"
          EXPIRE user_perms:U001           1800

  Total Redis round trips: 1 (pipeline)
```

### Invalidate — How Delete-by-User Works

```
  Caller has: user_id="U001"  (wants to wipe all permissions for this user)

  Step 1: SMEMBERS user_perms:U001
          → ["perm:U001:M005:A002:C001", "perm:U001:M003:A001:C001"]

  Step 2: DEL perm:U001:M005:A002:C001    ┐
          DEL perm:U001:M003:A001:C001    ┘ (pipelined)
          DEL user_perms:U001               (delete the index itself too)

  Total Redis round trips: 2
  (one SMEMBERS to find the keys, one pipeline to delete them all)
```

## Complete Go Implementation

### The Struct and Constants

```go
package permission

import (
    "context"
    "fmt"
    "time"

    "github.com/redis/go-redis/v9"
)

const (
    // permTTL is how long a permission Hash lives in Redis before
    // auto-expiring. 30 minutes is a sensible default for HR permission data
    // — fresh enough to reflect recent role changes, long enough to reduce
    // database load significantly.
    permTTL = 30 * time.Minute
)

// Permission is the data structure we store in Redis.
// Every field maps to one Hash field in Redis.
type Permission struct {
    UserID      string
    ModuleID    string
    AreaID      string
    CompanyID   string
    IsRead      bool
    IsWrite     bool
    IsSyncLog   bool
    IsBackDate  bool
}
```

### The Two Key Builders

```go
// permKey builds the exact Hash key for a permission.
// This is the key you use for reads and writes.
// Example: perm:U001:M005:A002:C001
func permKey(userID, moduleID, areaID, companyID string) string {
    return fmt.Sprintf("perm:%s:%s:%s:%s", userID, moduleID, areaID, companyID)
}

// userIndexKey builds the Set key that tracks all permission keys
// belonging to a user. This is the key you use during invalidation.
// Example: user_perms:U001
func userIndexKey(userID string) string {
    return fmt.Sprintf("user_perms:%s", userID)
}
```

These two functions are the entire schema of your Redis data. Every other function in this system calls one or both of them. Never hardcode a key string anywhere else.

### The Cache Service

```go
// Cache wraps the Redis client and exposes exactly three operations:
// Get, Set, and InvalidateUser. Nothing more, because nothing more is needed.
type Cache struct {
    rdb *redis.Client
}

func NewCache(rdb *redis.Client) *Cache {
    return &Cache{rdb: rdb}
}
```

### Get — Reading One Permission

```go
// Get fetches a single permission from Redis using all four identifiers.
// Returns (nil, nil) on a cache miss — the caller must then go to PostgreSQL.
// Returns (nil, err) only on a real Redis failure (network, timeout, etc.)
func (c *Cache) Get(ctx context.Context, userID, moduleID, areaID, companyID string) (*Permission, error) {
    key := permKey(userID, moduleID, areaID, companyID)

    // HGETALL returns all fields of the Hash as a map[string]string.
    // If the key does not exist, Redis returns an empty map — not an error.
    result, err := c.rdb.HGetAll(ctx, key).Result()
    if err != nil {
        return nil, fmt.Errorf("permission cache: HGETALL failed for key %s — %w", key, err)
    }

    // Empty map means the key does not exist in Redis. Cache miss.
    if len(result) == 0 {
        return nil, nil
    }

    // Decode the map into a Permission struct.
    perm := &Permission{
        UserID:     result["user_id"],
        ModuleID:   result["module_id"],
        AreaID:     result["area_id"],
        CompanyID:  result["company_id"],
        IsRead:     result["is_read"] == "1",
        IsWrite:    result["is_write"] == "1",
        IsSyncLog:  result["is_sync_log"] == "1",
        IsBackDate: result["is_back_date"] == "1",
    }

    return perm, nil
}
```

### Set — Writing One Permission

```go
// Set writes one permission to Redis and registers it in the user's index.
// Always call this AFTER the permission is safely written to PostgreSQL.
// Uses a pipeline so both commands go in a single network round trip.
func (c *Cache) Set(ctx context.Context, p Permission) error {
    dataKey  := permKey(p.UserID, p.ModuleID, p.AreaID, p.CompanyID)
    indexKey := userIndexKey(p.UserID)

    // Build the Hash fields. Redis Hash values are always strings,
    // so booleans become "1" or "0".
    fields := map[string]interface{}{
        "user_id":      p.UserID,
        "module_id":    p.ModuleID,
        "area_id":      p.AreaID,
        "company_id":   p.CompanyID,
        "is_read":      boolToStr(p.IsRead),
        "is_write":     boolToStr(p.IsWrite),
        "is_sync_log":  boolToStr(p.IsSyncLog),
        "is_back_date": boolToStr(p.IsBackDate),
    }

    // Pipeline: all four commands travel in one TCP packet.
    pipe := c.rdb.Pipeline()
    pipe.HSet(ctx, dataKey, fields)        // write the Hash data
    pipe.Expire(ctx, dataKey, permTTL)     // set TTL on the data
    pipe.SAdd(ctx, indexKey, dataKey)      // register in user index
    pipe.Expire(ctx, indexKey, permTTL)    // set TTL on the index

    if _, err := pipe.Exec(ctx); err != nil {
        return fmt.Errorf("permission cache: set failed for %s — %w", dataKey, err)
    }

    return nil
}
```

### SetMany — Writing a Batch of Permissions

This is what you call at login time, when you load all of a user's permissions from PostgreSQL and want to warm the cache in one shot.

```go
// SetMany writes multiple permissions to Redis in a single pipeline.
// This is the efficient path for cache warming — e.g. on user login,
// load all permissions from PostgreSQL and call SetMany once.
func (c *Cache) SetMany(ctx context.Context, perms []Permission) error {
    if len(perms) == 0 {
        return nil
    }

    pipe := c.rdb.Pipeline()

    for _, p := range perms {
        dataKey  := permKey(p.UserID, p.ModuleID, p.AreaID, p.CompanyID)
        indexKey := userIndexKey(p.UserID)

        fields := map[string]interface{}{
            "user_id":      p.UserID,
            "module_id":    p.ModuleID,
            "area_id":      p.AreaID,
            "company_id":   p.CompanyID,
            "is_read":      boolToStr(p.IsRead),
            "is_write":     boolToStr(p.IsWrite),
            "is_sync_log":  boolToStr(p.IsSyncLog),
            "is_back_date": boolToStr(p.IsBackDate),
        }

        pipe.HSet(ctx, dataKey, fields)
        pipe.Expire(ctx, dataKey, permTTL)
        pipe.SAdd(ctx, indexKey, dataKey)
        pipe.Expire(ctx, indexKey, permTTL)
    }

    // All N permissions are written in exactly one network round trip.
    if _, err := pipe.Exec(ctx); err != nil {
        return fmt.Errorf("permission cache: bulk set failed — %w", err)
    }

    return nil
}
```

### InvalidateUser — Deleting All Permissions for a User

This is the most important operation to get right. When a user's role changes, or an admin updates their permissions in the database, you call this function. It finds every permission key that belongs to the user and deletes them all.

```go
// InvalidateUser removes every cached permission for the given user.
// Call this immediately after updating or deleting permissions in PostgreSQL.
//
// Flow:
//   1. SMEMBERS user_perms:{userID}   → get all permission keys for this user
//   2. DEL each permission key        → pipelined
//   3. DEL user_perms:{userID}        → clean up the index itself
func (c *Cache) InvalidateUser(ctx context.Context, userID string) error {
    indexKey := userIndexKey(userID)

    // Step 1: Get the list of all permission keys for this user.
    dataKeys, err := c.rdb.SMembers(ctx, indexKey).Result()
    if err != nil {
        return fmt.Errorf("permission cache: SMEMBERS failed for user %s — %w", userID, err)
    }

    // If the index is empty, there is nothing cached for this user.
    // This is not an error — the cache may have already expired.
    if len(dataKeys) == 0 {
        return nil
    }

    // Step 2: Delete all permission Hashes and the index itself,
    // all in a single pipeline.
    pipe := c.rdb.Pipeline()

    for _, key := range dataKeys {
        pipe.Del(ctx, key)   // delete each perm:U001:M005:A002:C001 Hash
    }
    pipe.Del(ctx, indexKey)  // delete the user_perms:U001 Set itself

    if _, err := pipe.Exec(ctx); err != nil {
        return fmt.Errorf("permission cache: invalidation pipeline failed for user %s — %w", userID, err)
    }

    return nil
}
```

## Wiring It Into the Service Layer

Your Gin handlers never touch the cache directly. They call the `PermissionService`, which owns the cache-aside logic. The handler does not know or care whether the answer came from Redis or PostgreSQL.

```go
// PermissionService is what your Gin handlers call.
// It hides all cache logic behind a clean interface.
type PermissionService struct {
    repo  PermissionRepository // PostgreSQL
    cache *Cache
}

// GetPermission is the main read path.
// Try Redis first. On miss, go to PostgreSQL and warm the cache.
func (s *PermissionService) GetPermission(
    ctx context.Context,
    userID, moduleID, areaID, companyID string,
) (*Permission, error) {

    // ── Step 1: Try the cache ────────────────────────────────────────
    cached, err := s.cache.Get(ctx, userID, moduleID, areaID, companyID)
    if err != nil {
        // Redis had an error. Log it. Do NOT return an error to the caller.
        // Fall through to the database instead.
        // Redis failing should degrade performance, not break the feature.
        fmt.Printf("permission cache: read error (falling through to db): %v\n", err)
    }

    if cached != nil {
        return cached, nil // cache hit — return immediately
    }

    // ── Step 2: Cache miss — query PostgreSQL ────────────────────────
    perm, err := s.repo.GetPermission(ctx, userID, moduleID, areaID, companyID)
    if err != nil {
        return nil, fmt.Errorf("permission service: db query failed — %w", err)
    }

    if perm == nil {
        return nil, nil // permission does not exist at all
    }

    // ── Step 3: Warm the cache for next time ─────────────────────────
    // We do this in a goroutine so the caller gets their response immediately
    // without waiting for the Redis write to complete.
    go func() {
        writeCtx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
        defer cancel()

        if err := s.cache.Set(writeCtx, *perm); err != nil {
            fmt.Printf("permission cache: write failed: %v\n", err)
        }
    }()

    return perm, nil
}

// UpdatePermission writes the new permission to PostgreSQL,
// then invalidates the entire user's cache so stale data cannot be served.
func (s *PermissionService) UpdatePermission(ctx context.Context, p Permission) error {
    // Always write to the source of truth first.
    if err := s.repo.UpdatePermission(ctx, p); err != nil {
        return fmt.Errorf("permission service: db update failed — %w", err)
    }

    // Invalidate all cached permissions for this user.
    // We wipe the whole user rather than just the one key because a role change
    // typically affects multiple modules at once.
    if err := s.cache.InvalidateUser(ctx, p.UserID); err != nil {
        // Log but do not return an error. The database is the source of truth.
        // The cache will self-correct: stale entries expire in 30 minutes.
        fmt.Printf("permission cache: invalidation failed for user %s: %v\n", p.UserID, err)
    }

    return nil
}

// WarmCacheForUser loads all permissions for a user from PostgreSQL
// and pushes them into Redis at once. Call this at login time.
func (s *PermissionService) WarmCacheForUser(ctx context.Context, userID string) error {
    perms, err := s.repo.GetAllPermissionsForUser(ctx, userID)
    if err != nil {
        return fmt.Errorf("permission service: failed to load permissions for user %s — %w", userID, err)
    }

    if err := s.cache.SetMany(ctx, perms); err != nil {
        // Non-fatal. The app will still work — just without warm cache.
        fmt.Printf("permission cache: warm cache failed for user %s: %v\n", userID, err)
    }

    return nil
}
```

## The Full Flow, End to End

```
  ┌──────────────────────────────────────────────────────────────────────┐
  │  READ FLOW (happy path — cache hit)                                  │
  │                                                                      │
  │  Handler → GetPermission("U001","M005","A002","C001")                │
  │               │                                                      │
  │               ▼                                                      │
  │           cache.Get(...)                                             │
  │           HGETALL perm:U001:M005:A002:C001                           │
  │               │                                                      │
  │               ▼                                                      │
  │           Redis returns map → decode → return Permission             │
  │                                                                      │
  │  1 Redis command. Done.                                              │
  └──────────────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────────────┐
  │  READ FLOW (cache miss)                                              │
  │                                                                      │
  │  Handler → GetPermission("U001","M005","A002","C001")                │
  │               │                                                      │
  │               ▼                                                      │
  │           cache.Get(...) → Redis returns empty map → nil             │
  │               │                                                      │
  │               ▼                                                      │
  │           repo.GetPermission(...) → PostgreSQL query                 │
  │               │                                                      │
  │               ▼                                                      │
  │           return Permission to caller                                │
  │               │ (async goroutine)                                    │
  │               ▼                                                      │
  │           cache.Set(perm) → HSET + SADD in pipeline                 │
  │                                                                      │
  └──────────────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────────────┐
  │  INVALIDATION FLOW                                                   │
  │                                                                      │
  │  Admin updates permissions for U001                                  │
  │               │                                                      │
  │               ▼                                                      │
  │           repo.UpdatePermission(...) → PostgreSQL                    │
  │               │                                                      │
  │               ▼                                                      │
  │           cache.InvalidateUser("U001")                               │
  │               │                                                      │
  │               ▼                                                      │
  │           SMEMBERS user_perms:U001                                   │
  │           → ["perm:U001:M005:A002:C001",                             │
  │               "perm:U001:M003:A001:C001"]                            │
  │               │                                                      │
  │               ▼  (pipeline)                                          │
  │           DEL perm:U001:M005:A002:C001                               │
  │           DEL perm:U001:M003:A001:C001                               │
  │           DEL user_perms:U001                                        │
  │                                                                      │
  │  Next read for any of U001's permissions → cache miss → fresh DB hit │
  └──────────────────────────────────────────────────────────────────────┘
```

## Summary — The Complete Picture

```
  Write one permission:
  ┌────────────────────────────────────────────────────────────────┐
  │  HSET  perm:U001:M005:A002:C001   ← all 8 fields               │
  │  EXPIRE perm:U001:M005:A002:C001  1800                         │
  │  SADD  user_perms:U001  "perm:U001:M005:A002:C001"             │
  │  EXPIRE user_perms:U001  1800                                  │
  │  (4 commands, 1 pipeline, 1 round trip)                        │
  └────────────────────────────────────────────────────────────────┘

  Read one permission (your only query shape):
  ┌────────────────────────────────────────────────────────────────┐
  │  HGETALL perm:U001:M005:A002:C001                              │
  │  (1 command, 1 round trip)                                     │
  └────────────────────────────────────────────────────────────────┘

  Invalidate all permissions for a user:
  ┌────────────────────────────────────────────────────────────────┐
  │  SMEMBERS user_perms:U001        (round trip 1)                │
  │  DEL perm:U001:M005:A002:C001  ┐                               │
  │  DEL perm:U001:M003:A001:C001  ┤ pipelined (round trip 2)      │
  │  DEL user_perms:U001           ┘                               │
  └────────────────────────────────────────────────────────────────┘

  Key patterns (only two, ever):
    perm:{user_id}:{module_id}:{area_id}:{company_id}   → Hash (data)
    user_perms:{user_id}                                → Set  (index)
```

This is as simple and as fast as this problem gets. You have exactly two key patterns, three operations, and zero unnecessary complexity. Everything that was in the previous design that you do not need has been removed. This is the version you build.
