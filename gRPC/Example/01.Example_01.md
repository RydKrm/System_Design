# Setting Up gRPC in Go — From Zero to Two Talking Services

### A Complete Working Guide with Every Layer Explained

---

## Part 1 — Project Structure

Before writing a single line of Go, it helps to see how the files are laid out. In a real microservices project, each service lives in its own repository or at least its own directory. For this guide, two services share a monorepo so you can see them side by side.

```
grpc-demo/
│
├── go.mod                  ← module definition
│
├── proto/
│   └── user.proto          ← the contract between both services
│
├── pb/                     ← auto-generated from user.proto (never edit by hand)
│   ├── user.pb.go          ← message structs (GetUserRequest, UserResponse)
│   └── user_grpc.pb.go     ← service interface + client stub
│
├── user-service/
│   └── main.go             ← the gRPC SERVER (UserService on port :50051)
│
└── order-service/
    └── main.go             ← the gRPC CLIENT (OrderService, calls UserService)
```

The `proto/` directory is the centre of gravity. Everything else depends on it. The `pb/` directory is never written by hand — it is always produced by running `protoc` against the `.proto` file. Think of the `.proto` file as a TypeScript interface that works across any language.

Three things need to be installed before a single `.proto` file can become running Go code.

```bash
mkdir grpc-demo && cd grpc-demo
go mod init grpc-demo

# 5. Add the gRPC library
go get google.golang.org/grpc@latest
go get google.golang.org/protobuf@latest
```

## Part 3 — Why We Need `.proto` Files and How to Design Them

A `.proto` file is a formal contract. It is the document that both services agree on and compile against. Without it, Service A and Service B are two teams writing JSON and hoping they used the same field names — a system that fails silently and catastrophically in production.

The `.proto` file earns its keep in three ways. First, it is the only source of truth — there is no separate API document, no Wiki page, no Postman collection that can drift out of sync, because the running code is generated directly from this file. Second, it enforces strict types at compile time. If Service B's team renames `user_id` to `userId`, the generated Go code changes, and Service A's code will refuse to compile until it adapts. Third, it is language-neutral — the same `.proto` file can generate client code in Go, server code in Python, and another client in Node.js, all of them wire-compatible with zero extra work.

When designing `.proto` files, four rules are worth internalising from the start. Field numbers (the `= 1`, `= 2` after each field) are what actually get written onto the wire — the field name is never transmitted, only its number. This means field numbers must never be reused, even if you delete a field later. Fields numbered 1 through 15 use only a single byte on the wire, so the most frequently-used fields should claim those low numbers first. Every enum must have a zero value — proto3 always sets unrecognised fields to zero, so a zero-value that means "unknown" or "unspecified" is essential. And when you remove a field from a message, you mark its number `reserved` rather than simply deleting the line, which prevents a future developer from accidentally reusing that number and silently corrupting data for old clients still running in production.

```protobuf
// proto/user.proto

syntax = "proto3";

// Package name is used by protoc to namespace the generated code
package user;

// go_package tells protoc-gen-go where to put the generated .go files
// and what import path to use for them
option go_package = "grpc-demo/pb";


// ─── Messages ──────────────────────────────────────────────────────────
//
// Fields 1-15 cost 1 byte on the wire.
// Fields 16-2047 cost 2 bytes on the wire.
// Put your most-used fields at the low numbers.

message GetUserRequest {
  string user_id = 1;   // field 1 → tag byte: 0x0A
}

message UserResponse {
  string user_id = 1;   // field 1 → tag byte: 0x0A
  string name    = 2;   // field 2 → tag byte: 0x12
  string email   = 3;   // field 3 → tag byte: 0x1A
  int32  age     = 4;   // field 4 → tag byte: 0x20
}

// Example of safe field removal — number 5 was used before and is now retired
// reserved 5;
// reserved "phone_number";


// ─── Service ────────────────────────────────────────────────────────────
//
// The service block lists every remote-callable function.
// This is what protoc-gen-go-grpc uses to generate the client stub
// and the server interface.

service UserService {
  // Unary RPC: one request, one response — the most common pattern
  rpc GetUser (GetUserRequest) returns (UserResponse);
}
```

Once this file exists, you run one command to generate the Go code:

```bash
# Run from the root of grpc-demo/
protoc \
  --go_out=.          \    # generate user.pb.go (message structs)
  --go_opt=paths=source_relative \
  --go-grpc_out=.     \    # generate user_grpc.pb.go (service interfaces)
  --go-grpc_opt=paths=source_relative \
  proto/user.proto
```

This produces two files inside `pb/`. You never edit them. Every time the `.proto` file changes, you re-run this command and the generated files are overwritten.

## Part 4 — What the Generated Code Looks Like

It is important to read the generated code at least once, because it makes clear what the stub is actually doing on your behalf. The generated `user_grpc.pb.go` contains two key pieces.

The first is the **server interface** — a Go interface that your UserService must implement:

```go
// Generated in pb/user_grpc.pb.go — DO NOT edit
// This is what YOUR server code must satisfy
type UserServiceServer interface {
    GetUser(context.Context, *GetUserRequest) (*UserResponse, error)
    mustEmbedUnimplementedUserServiceServer()
}
```

The second is the **client stub** — a struct that OrderService uses to make calls:

```go
// Also generated — this is what YOUR client code calls
type userServiceClient struct {
    cc grpc.ClientConnInterface
}

func (c *userServiceClient) GetUser(ctx context.Context, in *GetUserRequest, opts ...grpc.CallOption) (*UserResponse, error) {
    out := new(UserResponse)
    err := c.cc.Invoke(ctx, "/user.UserService/GetUser", in, out, opts...)
    if err != nil {
        return nil, err
    }
    return out, err
}
```

Notice what `Invoke` does — it takes the method path string, the input struct, and an output struct pointer, and it handles all of the serialization, HTTP/2 framing, TCP transmission, and deserialization. All eighteen layers happen inside that single `Invoke` call.

## Part 5 — The User Service (gRPC Server)

```go
// user-service/main.go

package main

import (
    "context"
    "log"
    "net"

    "google.golang.org/grpc"
    "google.golang.org/grpc/codes"
    "google.golang.org/grpc/status"

    pb "grpc-demo/pb"
)

// ─── 1. Define the server struct ───────────────────────────────────────
//
// Embedding pb.UnimplementedUserServiceServer is required by proto3.
// It provides default implementations of all RPC methods that return
// "Unimplemented" errors. This way, if you add a new RPC to the .proto
// file but haven't written the handler yet, the service still compiles.

type userServer struct {
    pb.UnimplementedUserServiceServer
}

// ─── 2. Implement the handler ──────────────────────────────────────────
//
// This function signature is dictated entirely by the generated interface.
// You cannot change the argument types or return types — they come from
// the .proto file. Your only job here is business logic.

func (s *userServer) GetUser(ctx context.Context, req *pb.GetUserRequest) (*pb.UserResponse, error) {

    log.Printf("[UserService] GetUser called with user_id=%q", req.UserID)

    // Layer 12 equivalent: database call
    // In production this would be: db.QueryRowContext(ctx, "SELECT ...", req.UserId)
    // We simulate it inline here for clarity
    if req.UserId == "" {
        // gRPC has its own error codes — these travel back to the client
        // and are deserialized into a proper error on the other side
        return nil, status.Error(codes.InvalidArgument, "user_id must not be empty")
    }

    if req.UserId == "usr-0000" {
        return nil, status.Error(codes.NotFound, "user not found")
    }

    // Layer 13: build and return the response struct
    // gRPC will handle serialization, framing, and transmission automatically
    return &pb.UserResponse{
        UserId: req.UserId,
        Name:   "Karim Ahmed",
        Email:  "karim@example.com",
        Age:    28,
    }, nil
}

// ─── 3. Wire it together and start listening ───────────────────────────

func main() {
    // TCP listener — gRPC runs on top of TCP, just like HTTP/1.1 does
    // The standard convention for gRPC is port 50051
    listener, err := net.Listen("tcp", ":50051")
    if err != nil {
        log.Fatalf("[UserService] Failed to listen: %v", err)
    }

    // Create the gRPC server.
    // grpc.NewServer() is where you would also attach interceptors:
    //
    //   grpc.NewServer(
    //       grpc.UnaryInterceptor(authInterceptor),
    //       grpc.ChainUnaryInterceptor(loggingInterceptor, authInterceptor),
    //   )
    //
    grpcServer := grpc.NewServer()

    // Register our implementation with the gRPC server
    // This is what connects "/user.UserService/GetUser" → our GetUser() function
    pb.RegisterUserServiceServer(grpcServer, &userServer{})

    log.Println("[UserService] Listening on :50051")

    // Serve blocks forever, accepting connections and dispatching them
    // to the appropriate registered handler
    if err := grpcServer.Serve(listener); err != nil {
        log.Fatalf("[UserService] Serve failed: %v", err)
    }
}
```

## Part 6 — The Order Service (gRPC Client)

```go
// order-service/main.go

package main

import (
    "context"
    "log"
    "time"

    "google.golang.org/grpc"
    "google.golang.org/grpc/credentials/insecure"

    pb "grpc-demo/pb"
)

func main() {

    // ─── Layer 6: Establish the TCP + HTTP/2 connection ─────────────────
    //
    // grpc.Dial creates a persistent connection to the UserService.
    // In production you would use TLS credentials:
    //   grpc.WithTransportCredentials(credentials.NewTLS(tlsConfig))
    //
    // Here we use insecure (no TLS) for simplicity.
    //
    // grpc.WithBlock() means: wait until the connection is actually ready
    // before returning. Without it, Dial returns immediately and the first
    // RPC call would block instead.

    conn, err := grpc.Dial(
        "localhost:50051",
        grpc.WithTransportCredentials(insecure.NewCredentials()),
        grpc.WithBlock(),
        grpc.WithTimeout(5*time.Second),
    )
    if err != nil {
        log.Fatalf("[OrderService] Could not connect: %v", err)
    }
    defer conn.Close()
    log.Println("[OrderService] Connected to UserService at :50051")

    // ─── Layer 2: Create the client stub ────────────────────────────────
    //
    // NewUserServiceClient wraps the connection in the generated stub.
    // All subsequent calls go through this client object.
    // Under the hood it holds a reference to the conn and
    // uses it to invoke RPCs.

    userClient := pb.NewUserServiceClient(conn)

    // ─── Layer 1: Application code calls a gRPC method ──────────────────
    //
    // From this point, it looks exactly like a local function call.
    // The context carries deadlines and cancellation signals.
    // If the UserService takes longer than 3 seconds, this call will
    // automatically time out and return a codes.DeadlineExceeded error.

    ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
    defer cancel()

    log.Println("[OrderService] Calling GetUser(user_id='usr-4521')...")

    resp, err := userClient.GetUser(ctx, &pb.GetUserRequest{
        UserId: "usr-4521",
    })
    if err != nil {
        // gRPC errors carry a status code you can inspect
        // st, _ := status.FromError(err)
        // log.Printf("Code: %v  Message: %s", st.Code(), st.Message())
        log.Fatalf("[OrderService] GetUser failed: %v", err)
    }

    // ─── Layer 18: Final object delivered ───────────────────────────────
    //
    // resp is a fully typed *pb.UserResponse — no JSON parsing,
    // no map[string]interface{}, no type assertions needed.

    log.Printf("[OrderService] Response received:")
    log.Printf("  UserID : %s", resp.UserId)
    log.Printf("  Name   : %s", resp.Name)
    log.Printf("  Email  : %s", resp.Email)
    log.Printf("  Age    : %d", resp.Age)
}
```

## Part 9 — The Demo Program (Runnable Without gRPC Library)

The program below is a fully working demonstration of the cycle above. It uses only Go's standard library, replacing Protobuf with JSON and HTTP/2 with a hand-written TCP frame format. The structure, the log lines, and the data visible at each step are exactly what you would see in a real gRPC call — only the serialization format changes. This lets you run it right now without any dependency issues, see every byte on the wire, and understand exactly what each layer is doing.

```go
// main.go  (go run main.go)
// Demonstrates the full gRPC request-response cycle using
// only the Go standard library. Every layer is logged.

package main

import (
    "encoding/binary"
    "encoding/json"
    "fmt"
    "io"
    "log"
    "net"
    "sync"
    "time"
)

// ── Message definitions ───────────────────────────────────────────────
// In real gRPC these come from protoc-generated code (pb/user.pb.go).

type GetUserRequest struct {
    UserID string `json:"user_id"`
}

type UserResponse struct {
    UserID string `json:"user_id"`
    Name   string `json:"name"`
    Email  string `json:"email"`
    Age    int32  `json:"age"`
}

// ── Wire framing ──────────────────────────────────────────────────────
// Mirrors what HTTP/2 does: every frame has a length prefix + method tag.
// Real HTTP/2: [3-byte length][1-byte type][1-byte flags][4-byte stream ID][payload]
// Our simplified version: [4-byte length][1-byte method][payload]

const methodGetUser byte = 0x01

func writeFrame(conn net.Conn, method byte, payload []byte) error {
    buf := make([]byte, 5+len(payload))
    binary.BigEndian.PutUint32(buf[0:4], uint32(len(payload)))
    buf[4] = method
    copy(buf[5:], payload)
    _, err := conn.Write(buf)
    return err
}

func readFrame(conn net.Conn) (method byte, payload []byte, err error) {
    header := make([]byte, 5)
    if _, err = io.ReadFull(conn, header); err != nil {
        return
    }
    method = header[4]
    payload = make([]byte, binary.BigEndian.Uint32(header[0:4]))
    _, err = io.ReadFull(conn, payload)
    return
}

// ── USER SERVICE (server) ─────────────────────────────────────────────

func startUserService(ready chan struct{}) {
    ln, _ := net.Listen("tcp4", "127.0.0.1:50052")
    log.Println("[UserService] ✓ Listening on 127.0.0.1:50052")
    close(ready)

    conn, _ := ln.Accept()
    defer conn.Close()

    method, payload, _ := readFrame(conn)

    // Layer 7-8: TCP received, frame reassembled
    log.Printf("[UserService] Layer 7-8  │ TCP received, frame reassembled")
    log.Printf("[UserService]            │ method=0x%02X  payload_len=%d", method, len(payload))

    // Layer 9: Deserialize
    log.Printf("[UserService] Layer 9    │ Deserializing: % x", payload)
    var req GetUserRequest
    json.Unmarshal(payload, &req)
    log.Printf("[UserService]            │ → GetUserRequest{UserID: %q}", req.UserID)

    // Layer 10: Interceptor
    log.Printf("[UserService] Layer 10   │ Interceptor: auth check → PASSED")

    // Layer 11: Handler
    log.Printf("[UserService] Layer 11   │ Handler GetUser() invoked")

    // Layer 12: DB
    log.Printf("[UserService] Layer 12   │ SQL: SELECT * FROM users WHERE id='%s'", req.UserID)
    time.Sleep(5 * time.Millisecond) // simulate DB latency
    log.Printf("[UserService]            │ Row: {%s, Karim Ahmed, karim@example.com, 28}", req.UserID)

    // Layer 13: Build response
    resp := UserResponse{UserID: req.UserID, Name: "Karim Ahmed", Email: "karim@example.com", Age: 28}
    log.Printf("[UserService] Layer 13   │ Response: %+v", resp)

    // Layer 14: Serialize
    respBytes, _ := json.Marshal(resp)
    log.Printf("[UserService] Layer 14   │ Serialized %d bytes: % x", len(respBytes), respBytes)

    // Layer 15-16: Frame + TCP send
    writeFrame(conn, methodGetUser, respBytes)
    log.Printf("[UserService] Layer 15-16│ Frame written to TCP → sent ✓")
}

// ── ORDER SERVICE (client) ────────────────────────────────────────────

func runOrderService(done chan struct{}) {
    defer close(done)
    div()

    // Layer 1: Application code
    log.Println("[OrderService] Layer 1   │ App: GetUser(user_id='usr-4521')")

    // Layer 2: Stub
    req := GetUserRequest{UserID: "usr-4521"}
    log.Printf("[OrderService] Layer 2   │ Stub: method='/user.UserService/GetUser'")
    log.Printf("[OrderService]           │       message=%+v", req)

    // Layer 3: Serialize
    reqBytes, _ := json.Marshal(req)
    log.Printf("[OrderService] Layer 3   │ Serialized: % x", reqBytes)
    log.Printf("[OrderService]           │ ASCII:  %s", reqBytes)
    log.Printf("[OrderService]           │ Size: %d bytes (Protobuf ≈ 10 bytes)", len(reqBytes))

    // Layer 4: Frame
    log.Printf("[OrderService] Layer 4   │ Frame: [len=%d bytes][method=0x01][payload]", len(reqBytes))

    // Layer 5: Multiplexing
    log.Printf("[OrderService] Layer 5   │ HTTP/2: Stream ID=7 assigned")

    // Layer 6: TCP connect
    log.Printf("[OrderService] Layer 6   │ TCP: dialing 127.0.0.1:50052")
    conn, _ := net.Dial("tcp4", "127.0.0.1:50052")
    defer conn.Close()
    log.Printf("[OrderService]           │ Connected: local=%s", conn.LocalAddr())

    writeFrame(conn, methodGetUser, reqBytes)
    log.Printf("[OrderService]           │ Frame sent. Awaiting response...")

    div()

    // Layer 17: Receive + deserialize
    log.Printf("[OrderService] Layer 17  │ Reading response frame...")
    _, respBytes, _ := readFrame(conn)
    log.Printf("[OrderService]           │ Raw bytes: % x", respBytes)

    var resp UserResponse
    json.Unmarshal(respBytes, &resp)
    log.Printf("[OrderService]           │ Decoded: %+v", resp)

    // Layer 18: Final result
    div()
    fmt.Println()
    fmt.Println("  ╔══════════════════════════════════════════╗")
    fmt.Println("  ║  LAYER 18 — Application gets final result ║")
    fmt.Println("  ╠══════════════════════════════════════════╣")
    fmt.Printf( "  ║  resp.UserID  =  %-24s ║\n", resp.UserID)
    fmt.Printf( "  ║  resp.Name    =  %-24s ║\n", resp.Name)
    fmt.Printf( "  ║  resp.Email   =  %-24s ║\n", resp.Email)
    fmt.Printf( "  ║  resp.Age     =  %-24d ║\n", resp.Age)
    fmt.Println("  ╚══════════════════════════════════════════╝")
}

func div() { log.Println("─────────────────────────────────────────────────────") }

func main() {
    log.SetFlags(log.Ltime | log.Lmicroseconds)
    fmt.Println("\n  ┌─────────────────────────────────────────────┐")
    fmt.Println(  "  │  gRPC Cycle Demo: OrderService → UserService  │")
    fmt.Println(  "  └─────────────────────────────────────────────┘\n")

    ready := make(chan struct{})
    done  := make(chan struct{})
    var wg sync.WaitGroup

    wg.Add(1)
    go func() { defer wg.Done(); startUserService(ready) }()

    <-ready
    time.Sleep(50 * time.Millisecond)

    wg.Add(1)
    go func() { defer wg.Done(); runOrderService(done) }()

    <-done
    time.Sleep(100 * time.Millisecond)
}
```

## Part 11 — Adding an Interceptor (Middleware)

An interceptor in gRPC is what middleware is in Express or Gin. It runs before every handler on the server side, and optionally on the client side too. This is where authentication, logging, metrics, and distributed tracing belong — not inside the handler functions themselves.

```go
// Server-side interceptor — runs before every RPC handler

func loggingInterceptor(
    ctx context.Context,
    req interface{},
    info *grpc.UnaryServerInfo,
    handler grpc.UnaryHandler,
) (interface{}, error) {

    start := time.Now()
    log.Printf("[Interceptor] → %s  started", info.FullMethod)

    // Call the actual handler (or the next interceptor in the chain)
    resp, err := handler(ctx, req)

    duration := time.Since(start)
    if err != nil {
        log.Printf("[Interceptor] ✗ %s  error=%v  duration=%v", info.FullMethod, err, duration)
    } else {
        log.Printf("[Interceptor] ✓ %s  duration=%v", info.FullMethod, duration)
    }
    return resp, err
}

func authInterceptor(
    ctx context.Context,
    req interface{},
    info *grpc.UnaryServerInfo,
    handler grpc.UnaryHandler,
) (interface{}, error) {

    // Extract the "authorization" key from the incoming gRPC metadata
    // (metadata in gRPC is the equivalent of HTTP headers)
    md, ok := metadata.FromIncomingContext(ctx)
    if !ok {
        return nil, status.Error(codes.Unauthenticated, "missing metadata")
    }

    tokens := md["authorization"]
    if len(tokens) == 0 || tokens[0] != "Bearer my-secret-token" {
        return nil, status.Error(codes.Unauthenticated, "invalid token")
    }

    return handler(ctx, req) // token valid — proceed
}

// Attach interceptors when creating the server
grpcServer := grpc.NewServer(
    // ChainUnaryInterceptor runs them in order: logging first, then auth
    grpc.ChainUnaryInterceptor(loggingInterceptor, authInterceptor),
)
```

## Part 12 — Error Handling the gRPC Way

Unlike REST, where errors are just HTTP status codes and JSON bodies, gRPC has its own type-safe error system. Errors are created with `status.Error(code, message)` and decoded on the client with `status.FromError(err)`. This means the error code travels in the same Protobuf-encoded response, not as a side-channel status code, and it is fully typed on both ends.

```go
// Server: return typed errors
func (s *userServer) GetUser(ctx context.Context, req *pb.GetUserRequest) (*pb.UserResponse, error) {
    if req.UserId == "" {
        return nil, status.Error(codes.InvalidArgument, "user_id is required")
    }
    user, err := db.Find(req.UserId)
    if err == sql.ErrNoRows {
        return nil, status.Error(codes.NotFound, "user not found")
    }
    if err != nil {
        return nil, status.Error(codes.Internal, "database error")
    }
    return user, nil
}

// Client: inspect the error code
resp, err := userClient.GetUser(ctx, req)
if err != nil {
    st, ok := status.FromError(err)
    if ok {
        switch st.Code() {
        case codes.NotFound:
            log.Println("User does not exist")
        case codes.InvalidArgument:
            log.Println("Bad request:", st.Message())
        case codes.DeadlineExceeded:
            log.Println("Request timed out")
        default:
            log.Printf("gRPC error %v: %s", st.Code(), st.Message())
        }
    }
    return
}
```

## Part 13 — The Real Protobuf Binary vs This Demo's JSON

The demo uses JSON because it prints as readable text, letting you follow the bytes. Real gRPC uses Protobuf, and the difference is significant. Below is a side-by-side comparison of what `GetUserRequest{UserId: "usr-4521"}` looks like encoded in both formats:

```
JSON encoding (what the demo uses):
{"user_id":"usr-4521"}
7b 22 75 73 65 72 5f 69 64 22 3a 22 75 73 72 2d 34 35 32 31 22 7d
Total: 22 bytes

Protobuf encoding (what real gRPC uses):
0A 08 75 73 72 2D 34 35 32 31
│  │  └────────────────────┘
│  │       "usr-4521" in ASCII (8 bytes)
│  └── length prefix: 8 bytes follow
└── tag = (field_number=1 << 3) | wire_type=2  →  0x0A
Total: 10 bytes   ← 55% smaller than JSON
```

The field name `"user_id"` is never written anywhere in the Protobuf output. Only the tag `0x0A` appears, which encodes both the field number (1) and the wire type (2 = length-delimited string). Both client and server know from their compiled `.proto` definition that field number 1 in a `GetUserRequest` is `user_id`. This shared schema is what makes the compact encoding possible and safe.
