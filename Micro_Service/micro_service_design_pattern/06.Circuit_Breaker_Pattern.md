# The Circuit Breaker Pattern in Microservices

### Everything You Need to Know — Explained Like You Just Joined the Team

---

## A Story From the Physical World

Before we talk about software, think about the electrical panel in your home. It has a row of circuit breakers — small switches that monitor the current flowing through each circuit. When everything is normal, the breaker stays closed and electricity flows freely. But when a fault occurs — a short circuit, an overloaded wire, a damaged appliance drawing too much current — the breaker detects the problem and trips open. The circuit is broken. Electricity stops flowing to that section of the house.

This is not a failure. This is protection. The breaker did not cause the problem. The broken appliance caused the problem. The breaker prevented that one broken appliance from starting a fire, frying the wiring in the walls, and taking down the entire house with it.

After the trip, you do not leave the breaker open forever. You investigate the problem. You unplug the faulty appliance. Then you flip the breaker back on — carefully, watching to see if it holds. If the fault is gone, the breaker stays closed and power is restored. If the fault persists, the breaker trips again immediately.

The Circuit Breaker Pattern in software is this exact mechanism, applied to calls between microservices. And like the electrical breaker, it exists not to handle failures but to prevent them from spreading.

## The Problem: Cascading Failures in Microservices

In a distributed system with many services calling each other, a single unhealthy service can bring down the entire system — not by causing errors, but by causing the entire system to slow to a halt while every other service waits for it.

Let me show you exactly how this happens in our leave management system. Imagine the Approval Service becomes slow — perhaps its database is under heavy load and every query is taking 30 seconds to respond instead of the normal 50 milliseconds.

```
CASCADING FAILURE — How One Slow Service Kills Everything
──────────────────────────────────────────────────────────

Normal state (everything healthy):
  Client ──► API Gateway ──► Leave Service ──► Approval Service
             (50ms)          (50ms)            (50ms)
             Total: ~150ms

Approval Service becomes slow (DB overload):
  Client ──► API Gateway ──► Leave Service ──► Approval Service
             (30,000ms)      (30,000ms)        (30,000ms timeout)

What happens next:
  ┌──────────────────────────────────────────────────────────────┐
  │  Each request to Leave Service now holds a goroutine for     │
  │  30 seconds waiting for Approval Service to respond.         │
  │                                                              │
  │  100 requests/second arrive at Leave Service.                │
  │  Each holds a goroutine for 30 seconds.                      │
  │  After 10 seconds: 1,000 goroutines blocked.                 │
  │  After 20 seconds: 2,000 goroutines blocked.                 │
  │  After 30 seconds: 3,000 goroutines blocked, OOM crash.      │
  │                                                              │
  │  Leave Service crashes.                                      │
  │  Now API Gateway also blocks waiting for Leave Service.      │
  │  API Gateway crashes.                                        │
  │  The entire system is down.                                  │
  └──────────────────────────────────────────────────────────────┘

This is called a cascading failure.
One slow database caused the entire system to collapse.
```

The problem is not just that Approval Service is slow. The problem is that Leave Service keeps trying. Every incoming request to Leave Service generates a new attempt to reach Approval Service. Without any protection mechanism, Leave Service is willingly participating in its own destruction — and taking the entire system with it.

```
WITHOUT CIRCUIT BREAKER — The Cascade
─────────────────────────────────────────────────

     Client Requests (100/sec)
           │
           ▼
     API Gateway ──────────────────────────────────────────► blocks
           │
           ▼
     Leave Service ─────────────────────────────────────► blocks
           │   (goroutines accumulating, memory filling)
           ▼
     Approval Service ─────────────────────────────────► SLOW (30s)
           │
           ▼
     Balance Service (also calling Approval) ──────────► blocks
           │
           ▼
     Notification Service ──────────────────────────────► blocks

     Result: ENTIRE SYSTEM DOWN in ~30 seconds
     because of ONE slow database.
```

The Circuit Breaker Pattern prevents this cascade by detecting when a downstream service is unhealthy and immediately stopping all calls to it — not waiting, not retrying, but failing fast with a clear error. This releases the goroutines, keeps memory free, and allows the rest of the system to keep functioning normally.

```
WITH CIRCUIT BREAKER — Cascade Prevented
──────────────────────────────────────────

     Client Requests (100/sec)
           │
           ▼
     API Gateway ─────────────────────────────────► responds normally
           │
           ▼
     Leave Service
           │
           ├── Circuit Breaker for Approval Service: OPEN
           │   └── Returns immediate error: "Approval service unavailable"
           │       No goroutine held. No timeout waited.
           │       Response in < 1ms.
           │
           ▼
     Leave Service continues functioning normally
     for all operations that don't need Approval Service.

     Result: PARTIAL DEGRADATION, not total collapse.
     Users get a clear error for approval-related features.
     Everything else keeps working.
```

## The Three States of a Circuit Breaker

A circuit breaker is a state machine. It moves between three states based on what it observes about the health of the downstream service it is protecting.

```
CIRCUIT BREAKER STATE MACHINE
───────────────────────────────

              requests fail
  ┌─────────┐ threshold hit  ┌──────────┐
  │ CLOSED  │───────────────►│  OPEN    │
  │         │                │          │
  │ Normal  │                │ Fail     │
  │ traffic │◄───────────────│ fast, no │
  │ flows   │  probe request │ calls    │
  │ through │  succeeds      │ made     │
  └─────────┘                └──────────┘
       ▲                          │
       │                          │ after timeout
       │                          ▼
       │                    ┌──────────────┐
       │   probe succeeds   │  HALF-OPEN   │
       └────────────────────│              │
                            │ Allow one    │
          probe fails       │ probe        │
          ──────────────────│ request      │
          ▼                 │ through      │
       OPEN again           └──────────────┘
```

The **CLOSED** state is normal operation. Every request passes through to the downstream service. The circuit breaker counts failures and successes. As long as the failure rate stays below a configured threshold — say, less than 50% of requests failing — the breaker stays closed. Traffic flows normally.

The **OPEN** state is the tripped state. The downstream service is considered unhealthy. Every call to it is immediately rejected with a predefined error — no network connection is attempted, no goroutine is held waiting. This state lasts for a configured duration — say, 30 seconds — giving the downstream service time to recover.

The **HALF-OPEN** state is the testing state. After the open duration expires, the circuit breaker cautiously allows a small number of probe requests through to the downstream service. If those probes succeed, the downstream service has recovered and the breaker transitions back to CLOSED. If the probes fail, the downstream service is still unhealthy and the breaker transitions back to OPEN for another timeout period.

```
DETAILED STATE TRANSITIONS
────────────────────────────

CLOSED STATE:
  Every request ──► downstream service
  Track: success count, failure count, failure rate
  If failure_rate > threshold (e.g. 50%):
    transition ──► OPEN

OPEN STATE:
  Every request ──► immediate error (no network call)
  After timeout (e.g. 30 seconds):
    transition ──► HALF-OPEN

HALF-OPEN STATE:
  First N requests ──► downstream service (probes)
  If probe succeeds:
    reset counts
    transition ──► CLOSED
  If probe fails:
    transition ──► OPEN (reset the timeout)
```

## Implementing a Circuit Breaker in Go From Scratch

Before we use a library, let us build a basic circuit breaker ourselves. Understanding the internals makes you a better engineer than just knowing the API of a library.

```go
// circuitbreaker/circuit_breaker.go

package circuitbreaker

import (
    "context"
    "fmt"
    "sync"
    "time"
)

type State int

const (
    StateClosed   State = iota // Normal — calls pass through
    StateOpen                  // Tripped — calls fail immediately
    StateHalfOpen              // Testing — probe calls allowed
)

func (s State) String() string {
    switch s {
    case StateClosed:
        return "CLOSED"
    case StateOpen:
        return "OPEN"
    case StateHalfOpen:
        return "HALF-OPEN"
    default:
        return "UNKNOWN"
    }
}

type Config struct {
    Name             string
    MaxFailures      int           // failures before opening (e.g. 5)
    FailureThreshold float64       // failure rate before opening (e.g. 0.5 = 50%)
    MinRequests      int           // minimum requests before threshold applies (e.g. 10)
    OpenDuration     time.Duration // how long to stay OPEN (e.g. 30s)
    HalfOpenProbes   int           // how many probes to allow in HALF-OPEN (e.g. 1)
    Timeout          time.Duration // per-call timeout (e.g. 5s)
    OnStateChange    func(name string, from, to State) // optional callback
}

type counts struct {
    requests  int
    successes int
    failures  int
}

func (c *counts) failureRate() float64 {
    if c.requests == 0 {
        return 0
    }
    return float64(c.failures) / float64(c.requests)
}

func (c *counts) reset() {
    c.requests = 0
    c.successes = 0
    c.failures = 0
}

type CircuitBreaker struct {
    config       Config
    mu           sync.Mutex
    state        State
    counts       counts
    openedAt     time.Time  // when the breaker transitioned to OPEN
    halfOpenSent int        // how many probes already sent in HALF-OPEN
}

func New(config Config) *CircuitBreaker {
    return &CircuitBreaker{
        config: config,
        state:  StateClosed,
    }
}

// Execute wraps a call to a downstream service with circuit breaker protection
func (cb *CircuitBreaker) Execute(ctx context.Context, fn func(ctx context.Context) error) error {
    if err := cb.beforeCall(); err != nil {
        return err  // OPEN state — fail immediately
    }

    // Apply per-call timeout
    callCtx, cancel := context.WithTimeout(ctx, cb.config.Timeout)
    defer cancel()

    err := fn(callCtx)

    cb.afterCall(err)
    return err
}

func (cb *CircuitBreaker) beforeCall() error {
    cb.mu.Lock()
    defer cb.mu.Unlock()

    switch cb.state {
    case StateClosed:
        return nil  // let the call through

    case StateOpen:
        // Check if the open duration has expired
        if time.Since(cb.openedAt) >= cb.config.OpenDuration {
            cb.transitionTo(StateHalfOpen)
            cb.halfOpenSent = 1
            return nil  // allow this probe through
        }
        // Still open — fail fast
        return &CircuitBreakerOpenError{
            Name:      cb.config.Name,
            OpenedAt:  cb.openedAt,
            RetryAfter: cb.openedAt.Add(cb.config.OpenDuration),
        }

    case StateHalfOpen:
        if cb.halfOpenSent < cb.config.HalfOpenProbes {
            cb.halfOpenSent++
            return nil  // allow this probe through
        }
        // Already sent enough probes — reject until we get a result
        return &CircuitBreakerOpenError{
            Name:     cb.config.Name,
            OpenedAt: cb.openedAt,
        }
    }

    return nil
}

func (cb *CircuitBreaker) afterCall(err error) {
    cb.mu.Lock()
    defer cb.mu.Unlock()

    cb.counts.requests++

    if err != nil {
        cb.counts.failures++
        cb.onFailure()
    } else {
        cb.counts.successes++
        cb.onSuccess()
    }
}

func (cb *CircuitBreaker) onSuccess() {
    switch cb.state {
    case StateHalfOpen:
        // Probe succeeded — the downstream service has recovered
        cb.transitionTo(StateClosed)
        cb.counts.reset()

    case StateClosed:
        // Normal success — nothing to do
    }
}

func (cb *CircuitBreaker) onFailure() {
    switch cb.state {
    case StateClosed:
        // Check if we should trip the breaker
        if cb.counts.requests >= cb.config.MinRequests {
            if cb.counts.failures >= cb.config.MaxFailures ||
                cb.counts.failureRate() >= cb.config.FailureThreshold {
                cb.transitionTo(StateOpen)
            }
        }

    case StateHalfOpen:
        // Probe failed — downstream still unhealthy, go back to OPEN
        cb.transitionTo(StateOpen)
    }
}

func (cb *CircuitBreaker) transitionTo(next State) {
    if cb.state == next {
        return
    }

    from := cb.state
    cb.state = next

    if next == StateOpen {
        cb.openedAt = time.Now()
        cb.halfOpenSent = 0
    }

    if cb.config.OnStateChange != nil {
        go cb.config.OnStateChange(cb.config.Name, from, next)
    }
}

func (cb *CircuitBreaker) State() State {
    cb.mu.Lock()
    defer cb.mu.Unlock()
    return cb.state
}

// CircuitBreakerOpenError is returned when the breaker is OPEN
type CircuitBreakerOpenError struct {
    Name       string
    OpenedAt   time.Time
    RetryAfter time.Time
}

func (e *CircuitBreakerOpenError) Error() string {
    return fmt.Sprintf("circuit breaker '%s' is OPEN (opened at %s, retry after %s)",
        e.Name, e.OpenedAt.Format(time.RFC3339), e.RetryAfter.Format(time.RFC3339))
}
```

## Using the Circuit Breaker in Our gRPC Client Calls

In our project, services call each other via gRPC. The circuit breaker wraps every outbound gRPC call. Let us see exactly how the Leave Service protects its calls to the Approval Service.

```go
// leave/clients/approval_client.go

package clients

type ApprovalClient struct {
    conn    *grpc.ClientConn
    client  approvalpb.ApprovalServiceClient
    cb      *circuitbreaker.CircuitBreaker
    logger  *slog.Logger
    metrics *ClientMetrics  // for Prometheus/OpenTelemetry
}

func NewApprovalClient(conn *grpc.ClientConn) *ApprovalClient {
    cb := circuitbreaker.New(circuitbreaker.Config{
        Name:             "approval-service",
        MaxFailures:      5,
        FailureThreshold: 0.5,    // open if > 50% of requests fail
        MinRequests:      10,     // need at least 10 requests before applying threshold
        OpenDuration:     30 * time.Second,
        HalfOpenProbes:   1,
        Timeout:          5 * time.Second,
        OnStateChange: func(name string, from, to circuitbreaker.State) {
            slog.Warn("circuit breaker state changed",
                "breaker", name,
                "from", from.String(),
                "to", to.String(),
            )
            // In production: send alert to PagerDuty / Slack
        },
    })

    return &ApprovalClient{
        conn:   conn,
        client: approvalpb.NewApprovalServiceClient(conn),
        cb:     cb,
    }
}

func (c *ApprovalClient) CreateApproval(ctx context.Context, req *approvalpb.CreateApprovalRequest) (*approvalpb.Approval, error) {
    var result *approvalpb.Approval

    err := c.cb.Execute(ctx, func(callCtx context.Context) error {
        var callErr error
        result, callErr = c.client.CreateApproval(callCtx, req)
        return callErr
    })

    if err != nil {
        // Check if it's a circuit breaker open error (vs an actual gRPC error)
        var cbErr *circuitbreaker.CircuitBreakerOpenError
        if errors.As(err, &cbErr) {
            c.logger.Warn("approval service circuit breaker is open — failing fast",
                "retry_after", cbErr.RetryAfter,
            )
            return nil, status.Errorf(codes.Unavailable,
                "approval service is currently unavailable, please try again later")
        }
        return nil, err
    }

    return result, nil
}

func (c *ApprovalClient) GetApproval(ctx context.Context, leaveID string) (*approvalpb.Approval, error) {
    var result *approvalpb.Approval

    err := c.cb.Execute(ctx, func(callCtx context.Context) error {
        var callErr error
        result, callErr = c.client.GetApproval(callCtx, &approvalpb.GetApprovalRequest{
            LeaveId: leaveID,
        })
        return callErr
    })

    if err != nil {
        var cbErr *circuitbreaker.CircuitBreakerOpenError
        if errors.As(err, &cbErr) {
            return nil, status.Errorf(codes.Unavailable, "approval service unavailable")
        }
        return nil, err
    }

    return result, nil
}
```

## Using the Sony Gobreaker Library — Production Ready Out of the Box

Building your own circuit breaker from scratch is excellent for understanding. But in production, you should use a well-tested library. The most popular and clean circuit breaker library in the Go ecosystem is `sony/gobreaker`. It implements exactly the three-state machine we described, with all the edge cases handled correctly.

```bash
go get github.com/sony/gobreaker
```

```go
// leave/clients/approval_client_gobreaker.go

import "github.com/sony/gobreaker"

func NewApprovalClientWithGobreaker(conn *grpc.ClientConn, logger *slog.Logger) *ApprovalClient {
    settings := gobreaker.Settings{
        Name:        "approval-service",
        MaxRequests: 1,    // max requests in HALF-OPEN state (probes)
        Interval:    60 * time.Second,  // rolling window for counting failures
        Timeout:     30 * time.Second,  // how long to stay OPEN

        // ReadyToTrip is called on every failure — decides whether to OPEN
        ReadyToTrip: func(counts gobreaker.Counts) bool {
            failureRatio := float64(counts.TotalFailures) / float64(counts.Requests)
            return counts.Requests >= 10 && failureRatio >= 0.5
        },

        // OnStateChange is called whenever the state transitions
        OnStateChange: func(name string, from gobreaker.State, to gobreaker.State) {
            logger.Warn("circuit breaker changed state",
                "name", name,
                "from", from.String(),
                "to", to.String(),
            )
        },

        // IsSuccessful lets you control what counts as a success vs failure
        // Here: gRPC NOT_FOUND is not a circuit failure — the service is healthy
        // Only Unavailable/DeadlineExceeded count as circuit failures
        IsSuccessful: func(err error) bool {
            if err == nil {
                return true
            }
            st, ok := status.FromError(err)
            if !ok {
                return false  // non-gRPC error — treat as failure
            }
            switch st.Code() {
            case codes.NotFound,
                codes.InvalidArgument,
                codes.AlreadyExists,
                codes.PermissionDenied,
                codes.Unauthenticated:
                return true  // service responded correctly — not a circuit failure
            default:
                return false  // Unavailable, DeadlineExceeded, Internal — circuit failure
            }
        },
    }

    cb := gobreaker.NewCircuitBreaker(settings)

    return &ApprovalClient{
        conn:   conn,
        client: approvalpb.NewApprovalServiceClient(conn),
        cbImpl: cb,
        logger: logger,
    }
}

func (c *ApprovalClient) CreateApproval(ctx context.Context, req *approvalpb.CreateApprovalRequest) (*approvalpb.Approval, error) {
    result, err := c.cbImpl.Execute(func() (interface{}, error) {
        ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
        defer cancel()
        return c.client.CreateApproval(ctx, req)
    })

    if err != nil {
        if errors.Is(err, gobreaker.ErrOpenState) {
            return nil, status.Errorf(codes.Unavailable,
                "approval service is currently unavailable")
        }
        return nil, err
    }

    return result.(*approvalpb.Approval), nil
}
```

The `IsSuccessful` function deserves special attention. Without it, every error — including `NotFound` (which means the service is working fine and correctly reported that an entity does not exist) — counts as a circuit failure. This would cause your breaker to trip incorrectly. `IsSuccessful` lets you classify errors: business errors from a healthy service (NotFound, InvalidArgument) count as successes for circuit-breaking purposes, while infrastructure errors (Unavailable, DeadlineExceeded, Internal) count as real failures.

```
CORRECT ERROR CLASSIFICATION FOR CIRCUIT BREAKING
───────────────────────────────────────────────────

gRPC Error Code         Meaning for Circuit Breaker
────────────────────────────────────────────────────
NOT_FOUND               Service is healthy — entity just doesn't exist ── SUCCESS
INVALID_ARGUMENT        Service is healthy — request was bad ─────────── SUCCESS
ALREADY_EXISTS          Service is healthy — duplicate request ────────── SUCCESS
PERMISSION_DENIED       Service is healthy — not authorized ───────────── SUCCESS
UNAUTHENTICATED         Service is healthy — bad credentials ──────────── SUCCESS

UNAVAILABLE             Service is DOWN or unreachable ─────────────────── FAILURE
DEADLINE_EXCEEDED       Service is SLOW — taking too long ──────────────── FAILURE
INTERNAL                Service has a crash/panic ───────────────────────── FAILURE
RESOURCE_EXHAUSTED      Service is OVERLOADED ───────────────────────────── FAILURE
UNKNOWN                 Network problem or unknown crash ────────────────── FAILURE
```

## Circuit Breaker Variant 2 — Per-Endpoint Breakers

In the basic setup, you have one circuit breaker per downstream service. But consider the Approval Service: it has multiple endpoints — `CreateApproval`, `GetApproval`, `ListApprovals`, `DecideApproval`. If `CreateApproval` becomes slow because it does complex writes under load, you do not necessarily want to block `GetApproval` which is a simple read query. A per-service breaker would block all calls when only write operations are failing.

The solution is per-endpoint circuit breakers — one breaker per downstream service endpoint. Read operations and write operations can fail independently without affecting each other.

```go
// leave/clients/approval_client_per_endpoint.go

type ApprovalClientPerEndpoint struct {
    client          approvalpb.ApprovalServiceClient
    cbCreate        *gobreaker.CircuitBreaker
    cbGet           *gobreaker.CircuitBreaker
    cbList          *gobreaker.CircuitBreaker
    cbDecide        *gobreaker.CircuitBreaker
}

func NewApprovalClientPerEndpoint(conn *grpc.ClientConn) *ApprovalClientPerEndpoint {
    makeBreaker := func(name string, timeout time.Duration) *gobreaker.CircuitBreaker {
        return gobreaker.NewCircuitBreaker(gobreaker.Settings{
            Name:        name,
            MaxRequests: 1,
            Timeout:     timeout,
            ReadyToTrip: func(counts gobreaker.Counts) bool {
                return counts.Requests >= 5 &&
                    float64(counts.TotalFailures)/float64(counts.Requests) >= 0.6
            },
            IsSuccessful: isGrpcSuccessful,
        })
    }

    return &ApprovalClientPerEndpoint{
        client:   approvalpb.NewApprovalServiceClient(conn),
        cbCreate: makeBreaker("approval.create", 30*time.Second),  // write ops — longer recovery
        cbGet:    makeBreaker("approval.get",    10*time.Second),  // read ops — faster recovery
        cbList:   makeBreaker("approval.list",   10*time.Second),
        cbDecide: makeBreaker("approval.decide", 30*time.Second),
    }
}

func (c *ApprovalClientPerEndpoint) CreateApproval(ctx context.Context, req *approvalpb.CreateApprovalRequest) (*approvalpb.Approval, error) {
    result, err := c.cbCreate.Execute(func() (interface{}, error) {
        callCtx, cancel := context.WithTimeout(ctx, 5*time.Second)
        defer cancel()
        return c.client.CreateApproval(callCtx, req)
    })
    if err != nil {
        return nil, wrapCBError("approval.create", err)
    }
    return result.(*approvalpb.Approval), nil
}

func (c *ApprovalClientPerEndpoint) GetApproval(ctx context.Context, leaveID string) (*approvalpb.Approval, error) {
    result, err := c.cbGet.Execute(func() (interface{}, error) {
        callCtx, cancel := context.WithTimeout(ctx, 2*time.Second)
        defer cancel()
        return c.client.GetApproval(callCtx, &approvalpb.GetApprovalRequest{LeaveId: leaveID})
    })
    if err != nil {
        return nil, wrapCBError("approval.get", err)
    }
    return result.(*approvalpb.Approval), nil
}
```

```
PER-ENDPOINT BREAKERS — Independent Failure Isolation
───────────────────────────────────────────────────────

Approval Service under write pressure:

  cbCreate: OPEN   (writes failing — DB write contention)
  cbGet:    CLOSED (reads still working — read replica healthy)
  cbList:   CLOSED (reads still working)
  cbDecide: OPEN   (writes failing)

Result:
  CreateApproval ──► immediate error (cbCreate OPEN)  ✓
  GetApproval    ──► works normally  (cbGet CLOSED)   ✓
  ListApprovals  ──► works normally  (cbList CLOSED)  ✓

Without per-endpoint: ALL operations would be blocked
when only writes are slow.
```

## Circuit Breaker Variant 3 — With Fallback and Graceful Degradation

A circuit breaker that just returns an error is useful. A circuit breaker that returns a fallback response is transformative. When the breaker opens, instead of giving the user an error, you return a degraded but still useful response — maybe cached data, maybe a default value, maybe a response indicating that the feature is temporarily unavailable but the rest of the system keeps working.

This is called graceful degradation. The system degrades gracefully rather than collapsing completely.

```go
// leave/service/leave_service_with_fallback.go

type LeaveServiceWithFallback struct {
    approvalClient  *ApprovalClientPerEndpoint
    cache           *redis.Client
    logger          *slog.Logger
}

// GetLeaveWithApprovalStatus tries to get approval info, falls back to cached data
func (s *LeaveServiceWithFallback) GetLeaveWithApprovalStatus(
    ctx context.Context,
    leaveID string,
) (*LeaveDetailResponse, error) {

    leave, err := s.leaveRepo.GetLeave(ctx, leaveID)
    if err != nil {
        return nil, err
    }

    // Try to get approval info — this call is protected by circuit breaker
    approval, err := s.approvalClient.GetApproval(ctx, leaveID)

    if err != nil {
        if errors.Is(err, gobreaker.ErrOpenState) {
            // Circuit is open — use fallback strategy

            // Strategy 1: Try to get cached approval data from Redis
            cached, cacheErr := s.getCachedApproval(ctx, leaveID)
            if cacheErr == nil {
                s.logger.Info("approval service unavailable, using cached data",
                    "leave_id", leaveID,
                )
                return &LeaveDetailResponse{
                    Leave:          leave,
                    ApprovalStatus: cached.Status,
                    ApprovedBy:     cached.ApprovedBy,
                    DataFreshness:  "cached",  // tell the client the data may be stale
                }, nil
            }

            // Strategy 2: No cache available — return partial response with degraded info
            s.logger.Warn("approval service unavailable and no cache, returning partial data",
                "leave_id", leaveID,
            )
            return &LeaveDetailResponse{
                Leave:          leave,
                ApprovalStatus: "UNKNOWN",  // honest — we do not know
                DataFreshness:  "degraded",
                DegradationMsg: "Approval status temporarily unavailable",
            }, nil
        }

        // Real error (not a circuit breaker open) — propagate it
        return nil, err
    }

    // Success — cache the result for fallback use later
    s.cacheApproval(ctx, leaveID, approval)

    return &LeaveDetailResponse{
        Leave:          leave,
        ApprovalStatus: approval.Status,
        ApprovedBy:     approval.ApprovedBy,
        DataFreshness:  "live",
    }, nil
}

func (s *LeaveServiceWithFallback) getCachedApproval(ctx context.Context, leaveID string) (*CachedApproval, error) {

    if err != nil {
        return nil, err
    }
    var cached CachedApproval
    return &cached, json.Unmarshal(data, &cached)
}

    key := fmt.Sprintf("approval:cache:%s", leaveID)

        Status:     approval.Status,
        ApprovedBy: approval.ApprovedBy,
        CachedAt:   time.Now(),
```

## Circuit Breaker Variant 4 — At the API Gateway Level

In our project, the API Gateway sits in front of all services. It is the perfect place to add circuit breakers for the most important inter-service protection — because it handles all incoming traffic and has full visibility into the health of every downstream service.

When you add a circuit breaker at the API Gateway level, you protect the gateway itself from being dragged down by a slow microservice, and you can return meaningful fallback responses to clients without those requests ever reaching the overloaded service.

```go
// gateway/middleware/circuit_breaker_middleware.go

package middleware

type ServiceCircuitBreakers struct {
    breakers map[string]*gobreaker.CircuitBreaker
    mu       sync.RWMutex
    logger   *slog.Logger
}

func NewServiceCircuitBreakers(logger *slog.Logger) *ServiceCircuitBreakers {
    s := &ServiceCircuitBreakers{
        breakers: make(map[string]*gobreaker.CircuitBreaker),
        logger:   logger,
    }

    // Register a circuit breaker for every downstream service
    services := map[string]gobreaker.Settings{
        "employee-service": {
            Name:        "employee-service",
            MaxRequests: 2,
            Timeout:     30 * time.Second,
            ReadyToTrip: standardTrip,
            OnStateChange: s.onStateChange,
        },
        "leave-service": {
            Name:        "leave-service",
            MaxRequests: 2,
            Timeout:     30 * time.Second,
            ReadyToTrip: standardTrip,
            OnStateChange: s.onStateChange,
        },
        "approval-service": {
            Name:        "approval-service",
            MaxRequests: 1,
            Timeout:     60 * time.Second,  // give it longer to recover — complex service
            ReadyToTrip: standardTrip,
            OnStateChange: s.onStateChange,
        },
        "balance-service": {
            Name:        "balance-service",
            MaxRequests: 1,
            Timeout:     30 * time.Second,
            ReadyToTrip: standardTrip,
            OnStateChange: s.onStateChange,
        },
    }

    for name, settings := range services {
        s.breakers[name] = gobreaker.NewCircuitBreaker(settings)
    }

    return s
}

func (s *ServiceCircuitBreakers) Middleware(serviceName string) func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            cb := s.getBreaker(serviceName)

            _, err := cb.Execute(func() (interface{}, error) {
                // Capture the response to check if the downstream service failed
                recorder := httptest.NewRecorder()
                next.ServeHTTP(recorder, r)

                // Treat 5xx responses as circuit failures
                if recorder.Code >= 500 {
                    return nil, fmt.Errorf("downstream returned %d", recorder.Code)
                }

                // Copy the captured response to the real writer
                for k, v := range recorder.Header() {
                    w.Header()[k] = v
                }
                w.WriteHeader(recorder.Code)
                w.Write(recorder.Body.Bytes())
                return nil, nil
            })

            if err != nil {
                if errors.Is(err, gobreaker.ErrOpenState) {
                    w.Header().Set("Content-Type", "application/json")
                    w.Header().Set("Retry-After", "30")
                    w.WriteHeader(http.StatusServiceUnavailable)
                    json.NewEncoder(w).Encode(map[string]interface{}{
                        "error":       "service_temporarily_unavailable",
                        "service":     serviceName,
                        "message":     "This service is temporarily unavailable. Please try again in 30 seconds.",
                        "retry_after": 30,
                    })
                    return
                }
            }
        })
    }
}

func (s *ServiceCircuitBreakers) onStateChange(name string, from, to gobreaker.State) {
    s.logger.Warn("gateway circuit breaker state changed",
        "service", name,
        "from", from.String(),
        "to", to.String(),
    )
    // In production: push metric to Prometheus, alert Slack/PagerDuty
}

func standardTrip(counts gobreaker.Counts) bool {
    // Open after 5 consecutive failures OR > 50% failure rate with at least 10 requests
    return counts.ConsecutiveFailures >= 5 ||
        (counts.Requests >= 10 &&
            float64(counts.TotalFailures)/float64(counts.Requests) >= 0.5)
}

func (s *ServiceCircuitBreakers) getBreaker(name string) *gobreaker.CircuitBreaker {
    s.mu.RLock()
    defer s.mu.RUnlock()
    return s.breakers[name]
}
```

## Circuit Breaker Variant 5 — With OpenTelemetry Observability

A circuit breaker that trips silently is nearly useless in production. You need to know when it trips, how often, how long it stays open, and which services are causing problems. Since our project already uses OpenTelemetry, we wire the circuit breaker events into our observability stack.

```go
// circuitbreaker/observable_breaker.go

package circuitbreaker

import (
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/attribute"
    "go.opentelemetry.io/otel/metric"
    "go.opentelemetry.io/otel/trace"
)

type ObservableCircuitBreaker struct {
    inner        *gobreaker.CircuitBreaker
    name         string
    tracer       trace.Tracer
    stateGauge   metric.Int64ObservableGauge     // current state (0=closed, 1=open, 2=halfopen)
    tripCounter  metric.Int64Counter             // how many times it has tripped
    rejectCounter metric.Int64Counter            // how many calls were rejected (fast-fail)
    successCounter metric.Int64Counter
    failureCounter metric.Int64Counter
    logger       *slog.Logger
}

func NewObservable(name string, settings gobreaker.Settings, logger *slog.Logger) *ObservableCircuitBreaker {
    meter := otel.Meter("circuit_breaker")
    tracer := otel.Tracer("circuit_breaker")

    stateGauge, _    := meter.Int64ObservableGauge("circuit_breaker.state",
        metric.WithDescription("Current state: 0=CLOSED, 1=OPEN, 2=HALF-OPEN"))
    tripCounter, _   := meter.Int64Counter("circuit_breaker.trips_total",
        metric.WithDescription("Total number of times the circuit breaker has tripped"))
    rejectCounter, _ := meter.Int64Counter("circuit_breaker.rejected_calls_total",
        metric.WithDescription("Calls rejected because the breaker was OPEN"))
    successCounter, _ := meter.Int64Counter("circuit_breaker.successes_total")
    failureCounter, _ := meter.Int64Counter("circuit_breaker.failures_total")

    ocb := &ObservableCircuitBreaker{
        name:           name,
        tracer:         tracer,
        stateGauge:     stateGauge,
        tripCounter:    tripCounter,
        rejectCounter:  rejectCounter,
        successCounter: successCounter,
        failureCounter: failureCounter,
        logger:         logger,
    }

    // Register original OnStateChange and wrap it with metrics
    originalOnChange := settings.OnStateChange
    settings.OnStateChange = func(cbName string, from, to gobreaker.State) {
        attrs := attribute.NewSet(
            attribute.String("circuit_breaker.name", cbName),
            attribute.String("from_state", from.String()),
            attribute.String("to_state", to.String()),
        )
        ctx := context.Background()

        if to == gobreaker.StateOpen {
            tripCounter.Add(ctx, 1, metric.WithAttributeSet(attrs))
        }

        logger.Warn("circuit breaker state changed",
            "name", cbName,
            "from", from.String(),
            "to", to.String(),
        )

        if originalOnChange != nil {
            originalOnChange(cbName, from, to)
        }
    }

    ocb.inner = gobreaker.NewCircuitBreaker(settings)
    return ocb
}

func (ocb *ObservableCircuitBreaker) Execute(ctx context.Context, fn func() (interface{}, error)) (interface{}, error) {
    // Create a span for this circuit-breaker-protected call
    ctx, span := ocb.tracer.Start(ctx, fmt.Sprintf("circuit_breaker.%s", ocb.name))
    defer span.End()

    attrs := []attribute.KeyValue{
        attribute.String("circuit_breaker.name", ocb.name),
        attribute.String("circuit_breaker.state", ocb.inner.State().String()),
    }

    result, err := ocb.inner.Execute(fn)

    if err != nil {
        if errors.Is(err, gobreaker.ErrOpenState) {
            ocb.rejectCounter.Add(ctx, 1, metric.WithAttributes(attrs...))
            span.SetAttributes(attribute.Bool("circuit_breaker.rejected", true))
        } else {
            ocb.failureCounter.Add(ctx, 1, metric.WithAttributes(attrs...))
        }
        span.RecordError(err)
    } else {
        ocb.successCounter.Add(ctx, 1, metric.WithAttributes(attrs...))
    }

    span.SetAttributes(
        attribute.String("circuit_breaker.final_state", ocb.inner.State().String()),
    )

    return result, err
}
```

## The Relationship Between Retry, Timeout, and Circuit Breaker

These three patterns are always discussed together because they are complementary. Each one handles a different aspect of failure. Using them together — and in the right combination — is what makes a truly resilient service.

A **Timeout** defines the maximum time you are willing to wait for a downstream call. Without a timeout, a single hung call can hold a goroutine forever. Timeouts are the first line of defense.

A **Retry** gives a failed call a second (or third) chance. It handles transient failures — network blips, momentary overloads that clear within milliseconds. But retries without a circuit breaker can amplify load on an already struggling service. If 1,000 requests all get retried three times each, you have turned 1,000 calls into 3,000 calls on a service that was already failing.

A **Circuit Breaker** stops retries when a service is demonstrably unhealthy. Once the breaker opens, neither the original call nor any retries go through. The load on the downstream service drops to zero, giving it the breathing room to recover.

```
RETRY + TIMEOUT + CIRCUIT BREAKER — Layered Defense
──────────────────────────────────────────────────────

  Incoming gRPC call to Approval Service
         │
         ▼
  Circuit Breaker OPEN?
  ├── YES ──► Fail fast immediately (2ms response) ✓
  │
  └── NO — proceed
         │
         ▼
  Call with 5-second Timeout
         │
         ├── Success ──► Return result ✓
         │
         └── Failure (timeout or error)
                  │
                  ▼
             Retry? (max 2 retries, exponential backoff)
             ├── Retry 1: wait 100ms, try again
             │     ├── Success ──► Return result ✓
             │     └── Failure ──► Record against circuit breaker
             │
             └── Retry 2: wait 200ms, try again
                   ├── Success ──► Return result ✓
                   └── Failure ──► Record against circuit breaker
                                       │
                                       ▼
                              Circuit breaker now has 3 failures.
                              If threshold exceeded: OPEN.
                              Next call: immediate fail-fast.
```

In Go with gRPC, you implement this layered defense like this:

```go
// leave/clients/resilient_approval_client.go

type ResilientApprovalClient struct {
    client         approvalpb.ApprovalServiceClient
    cb             *gobreaker.CircuitBreaker
    maxRetries     int
    baseDelay      time.Duration
    callTimeout    time.Duration
}

func (c *ResilientApprovalClient) CreateApproval(ctx context.Context, req *approvalpb.CreateApprovalRequest) (*approvalpb.Approval, error) {
    var lastErr error

    for attempt := 0; attempt <= c.maxRetries; attempt++ {
        if attempt > 0 {
            // Exponential backoff before retry
            backoff := c.baseDelay * time.Duration(1<<(attempt-1))  // 100ms, 200ms, 400ms
            jitter := time.Duration(rand.Int63n(int64(backoff / 2))) // add jitter
            select {
            case <-time.After(backoff + jitter):
            case <-ctx.Done():
                return nil, ctx.Err()
            }
        }

        result, err := c.cb.Execute(func() (interface{}, error) {
            callCtx, cancel := context.WithTimeout(ctx, c.callTimeout)
            defer cancel()
            return c.client.CreateApproval(callCtx, req)
        })

        if err == nil {
            return result.(*approvalpb.Approval), nil
        }

        lastErr = err

        // Do not retry if the circuit breaker is open — it's already managing backoff
        if errors.Is(err, gobreaker.ErrOpenState) {
            return nil, err
        }

        // Do not retry on business errors — they will not change with retry
        if st, ok := status.FromError(err); ok {
            switch st.Code() {
            case codes.InvalidArgument,
                codes.NotFound,
                codes.AlreadyExists,
                codes.PermissionDenied:
                return nil, err  // no point retrying these
            }
        }

        // Retry on: Unavailable, DeadlineExceeded, Internal, ResourceExhausted
    }

    return nil, fmt.Errorf("all %d attempts failed, last error: %w", c.maxRetries+1, lastErr)
}
```

## What the Circuit Breaker Does Not Do

The Circuit Breaker Pattern is about resilience and failure isolation. It is worth being explicit about what it is not, because sometimes people expect it to solve problems it was never designed for.

The circuit breaker does not fix the underlying problem. If the Approval Service is down, the circuit breaker prevents a cascade — but the Approval Service is still down. The circuit breaker buys time for the problem to be fixed, and it prevents the problem from spreading. But it does not heal the sick service.

The circuit breaker does not replace proper error handling. It is one layer in a defense-in-depth strategy alongside timeouts, retries, health checks, and graceful degradation. Using a circuit breaker without also setting timeouts means your goroutines still hang during the window before the breaker trips. All three — timeout, retry, circuit breaker — must be used together.

The circuit breaker does not make eventually-consistent operations safe. If you are in a SAGA and the circuit breaker prevents a step from executing, the SAGA must handle that through its compensation mechanism. The circuit breaker opens the failure path cleanly — the SAGA orchestrator still needs to respond appropriately.

What the circuit breaker does is give your system the ability to detect and contain failure quickly, fail fast with clarity rather than slowly with confusion, protect healthy services from being dragged down by unhealthy ones, and give the failing service the quiet it needs to recover. In a system with twelve or more services calling each other, none of that is optional. It is the difference between a five-minute incident and a two-hour outage.
